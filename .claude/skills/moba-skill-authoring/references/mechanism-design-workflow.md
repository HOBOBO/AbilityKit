# 机制设计、原语复用与组合审查

用于机制规划、跨模块审查，以及投射物/区域/召唤物/移动等扩展。普通数值或引用修复只检查受影响链，不要求重新规划整个英雄。

准入规则仍以 [机制治理](../../../../Docs/MobaMechanismGovernance.md) 为准。跨机制理由、当前证据索引和建设路线见 [机制扩展架构分析](../../../../Docs/MobaMechanismExtensionArchitecture.md)。其中“建设建议”是方案，不是已经批准的机制。

## 1. 先把需求分解为几条生命周期

按主语分别列角色、单次施法、弹体/区域/召唤物/运动源、外部贡献及表现。每条只指定一个生命周期所有者，再说明它怎样调用其它模块。

| 需求部分 | 优先检查 | 判定边界 |
|---|---|---|
| 感知、选目标、选技能、追击/跟随 | Brain/行为树、Query、意图仲裁 | 输出意图，执行继续走正式移动/Cast 入口 |
| 角色模式、受控/恢复、跨输入阶段 | 角色 HFSM 与声明绑定 | 条件与优先级决定转换；复用既有状态，不为每个动画加状态 |
| 一次施法的准备/等待/提交/取消 | SkillPipeline phase | 一次输入内的有界流程；独立下一发重新建 Cast |
| 命中/到达/状态边界/周期事件效果 | Trigger Authoring 与领域动作 | 有明确事件/调用与执行 scope，不托管整段施法 |
| 独立对象的飞行、等待、返回、终结 | Projectile/Area 领域与对象状态机 | 普通运动策略足够时无需增加状态图 |
| 有起止的位移、光环、Buff 等实例 | Continuous 与领域 runtime | 对象自己的计时和撤销，不靠长 Flow 保活 |
| 创建/容量/继承/销毁/补偿 | 已有领域服务和 Actor 链 | Trigger 发请求，不自行拼结构事务 |
| 世界帧推进与派生结算 | 正式 System 树 | 不新增独立时钟、补 Tick 或第二条结算链 |
| 动画/VFX/HUD 和恢复 | 状态动作、Timeline 表现分流、Cue | 只消费权威状态，完成回调不提交玩法 |

不要按持续秒数决定 HFSM 或 Pipeline。一次输入的有界 Channel 可以用 Pipeline；进入模式后多次独立射击的模式由 HFSM/持久状态管理。父 Flow 结束也不等于原 Cast 上下文和已提交子对象立即释放，先查 child/retain 合同。

区分 SkillPipeline、MotionPipeline、通用 Flow、角色 HFSM 与对象 `HierarchicalProfile`，不能按同名节点推断相同调度、并行或恢复语义。

### 固定边界与包外扩展

涉及机制类型增长、框架上移、拆包或包外接入时，再读 [固定边界与包外扩展方案](../../../../Docs/MobaFrameworkExtensionBoundaries.md)。本轮用户方向是稳定契约进框架、变化能力允许包外扩展；具体新增 API/schema/恢复语义仍按治理确认。

- 分别记录基础执行契约、可选能力、MOBA 适配/扩展和内容组合。多个英雄复用不自动意味着应该成为基础包默认能力。
- 固定执行/提交/生命周期/结果/恢复边界；算法、叶动作/条件和策略在这些边界内扩展。闭合的结构分支可以保留，不因每种内容效果扩充核心 enum/DTO/执行器。
- 代表组合只做接口验收，不为 Projectile→Area→Motion 等排列组合创建框架类型或万能 Profile。
- 查公开 API 之外，还查外部程序集发现/显式安装、默认模块合并、作者 schema、编译校验、发布、状态恢复和 Player/AOT 消费。接口可实现不等于生产包外可用。
- 新扩展优先只改其实现/必要适配、应用安装和内容；基础包不反向依赖扩展。现有接口不足时提出最小接点方案，不先造统一插件引擎。
- 不擅自把现有覆盖注册改成拒绝、不承诺世界隔离或热卸载；这些行为依注册表现状逐项确认。有状态扩展按原领域所有权恢复，不持续向核心快照追加策略专属字段。
- 包外验证使用真实外部程序集和公开 API；不靠复制源码、friend assembly 或 Editor 反射代替独立消费。

涉及抽象成本或规模性能时，读 [性能与运行时实例化边界](../../../../Docs/MobaFrameworkExtensionBoundaries.md#64-边界对管理有用不要求运行时层层实例化)。职责阶段不要求各自创建对象/事件/Tick；瞬时路径直接执行，跨帧才保存必要过程状态。分别评估调度扫描、策略分派、必要领域工作、分配/缓存及启用的恢复成本，以相同行为的目标构建对照验证，不承诺“接口调用可忽略”或虚构开销比例。选择缓存、批处理、池化、队列结构时保持采样、顺序、RNG、生命周期与恢复等价，不以性能为由减损业务合同。

项目明确能力方向、要求按需去掉动态成本时，按 [支持子集与实现替换](../../../../Docs/MobaFrameworkExtensionBoundaries.md#65-项目方向确定后可选择能力子集并替换执行实现) 区分能力裁剪和等价实现替换。优先构建/装配/加载时选择，检查被裁能力的内容引用并明确拒绝；保留采样、顺序、来源、提交和所需恢复合同。DI 绑定不保证消除接口分派，Feature 开关不证明已裁掉代码/系统；用同一作者源和合同场景验证固定实现，不按英雄身份建专用后端，不先造多后端平台。具体新接点仍须确认。

## 2. 为真正影响结果的数据找所有者

对受影响字段填写以下信息，不新增一份与领域数据竞争的“统一技能状态”：

| 字段/key | 类型/单位 | 唯一权威写入者 | scope/来源键 | 采样时机 | 结束与撤销 | 恢复与重绑 |
|---|---|---|---|---|---|---|
| 按当前场景填写 | 明确帧/毫秒/定点等 | 当前真实存储及消费者 | Actor/Cast/对象/外部来源等 | 输入/准备/提交/创建/事件/实时 | 正常/取消/死亡/替换 | 已有 Provider/Command 与支持边界 |

优先核对几个容易选错的位置：

- HP 当前值读 `ResourceContainer`，不是属性基线；冷却/充能按已有 loadout/economy 状态归属，不随单次 Flow 销毁。
- 角色本地模式/计数与外部 Buff/Modifier 贡献分别说明。已有稳定来源 Toggle、Counter 投影可以复用；不为无自然寿命的本地记忆强行制造 Buff。
- 参数服务中的贡献、系统事实、准确 Cast 快照和合成结果不是同一层。写来源贡献后重评估条件，不直接指定 HFSM 目标状态。
- 暂时查询结果留在现有局部 scope；跨帧 Brain 记忆需声明持有与恢复。不要把跨实体资格和生命周期变成任意 Blackboard key。
- ECS、Service 和 Runtime 都可以持有各自领域状态。回滚恢复按既有归属接入，不因要序列化就强迁 ECS。
- 接入回滚或实质修改已声明支持回滚的跨帧状态时，按[业务回滚契约第 2.1、5 节](../../framesync-prediction-rollback/business-state-rollback.md)分类权威、派生、临时和运行依赖；检查独立备份、正常业务与恢复入口隔离、引用失效及失败拒绝。普通业务保留写法自由；需要回滚时诊断具体不支持项并补齐，不能启用后靠 Provider 猜测隐藏状态。

若现有规范对来源、合成、死亡重置或存续规则有冲突，记录冲突并提案；本参考不替用户选择新语义。

## 3. 查证能力，不靠名字判定“已支持”

对每个机制分别检查：

1. 规范与批准范围；旧方案状态是否已被后续记录更新。
2. 真实可编辑作者源及发布链；不要把生成 JSON 当输入。
3. Schema/编译器是否接受；实际消费者是否使用每个相关字段。
4. 领域算法、时间、身份、来源、资格与清理是否接通。
5. 生产组合测试和适用的逻辑/表现结果证据。
6. 回滚启用时的字段、结构、恢复名单与重演；跨会话能力另列。

每项记录“有证据 / 缺证据 / 明确拒绝 / 不适用”。测试源码存在只能作为验证入口，不能写成本轮已通过。旧报告中的通过率、模块数与未实现判断不自动代表当前工作树。

已知检索陷阱：

- `SpawnSummonSchema` 解析了一组字段，但当前动作已消费 `DurationMs`，`IntervalMs/TotalCount/QueryTemplateId` 等仍需逐项对照。不能把 `duration_ms` 当周期召唤总长，不能把未消费字段直接启用成新机制。
- `ProjectileHitPolicyFactory` 已有公开注册入口。自定义策略仍需核对作者化、冻结、恢复描述与 codec，开放 API 不能替代机制批准。
- 近期 Projectile/Launcher 恢复仍在演进。代码、治理摘要、方案状态与验收不一致时，逐条登记，不自动放宽资格，也不重复申请已有明确批准的同一范围。
- 历史英雄特例收敛记录只覆盖其审计链。具体 ID 的内容绑定合法；是否违规要追到是否按身份增加算法，不能只靠名字搜索。

## 4. 按领域选择需要检查的契约

### Projectile / Area

分开发射 schedule、飞行策略、碰撞参与、Ignore/Hit/Block 响应、命中身份/次数、对象阶段、效果与清理。验证过滤和资格消费顺序，不在每个效果里另造去重集合。

到达派生区域时，核对原 Cast 来源、retain、唯一到达、Spawn 和首次物理检测。当前首次空间检测遵循下一次正常物理 Tick；共同结算可以完成本帧 Spawn，但不补物理。

先读 [正式系统顺序](../../../../Unity/Packages/com.abilitykit.demo.moba.runtime/Runtime/Docs/SystemOrderGuide.md)。新机制若改变碰撞采样、响应、阶段或恢复对象范围，提交独立方案。

### Summon / Brain

召唤服务管身份、构造、继承、容量、来源与终结；Brain 管事实、候选、条件、瞄准与意图，输出再走正式执行。主人死亡/超时清理不塞进行为树节点。

涉及出生过程、分批/周期、阵型落点或准备完成时，读 [召唤生产与入场规划](../../../../Docs/MobaSummonProductionLifecyclePlan.md)。区分生产过程、单项构造/入场、活动召唤物；瞬时路径不强加任务、Launcher 或额外一帧。分别声明：

- 位置/朝向与模板/继承的采样时点；计划/创建/激活/存活数量；失败重试与容量占用/预留。
- 受理、创建、激活和生产结束的返回/通知；保留当前 ActorId 输出语义，不偷换成未来过程 handle。
- 延迟创建、先创建后激活、逻辑即时而表现渐入三种方式；准备期的行动/目标/受伤/碰撞/被动/光环/寿命门禁，不能只禁 Brain。
- 未来项、产物各自的来源/retain、取消与主人死亡策略；恢复生产游标和入场事实，不补发历史 Spawn/Ready。

当前 Unpublished Actor 构造仍注册实体/碰撞，不是隔离准备区；pending Spawn 输出队列不是未来生产队列。位置/图案/节奏等策略应通过领域提交生效，不能自行创建实体或推进时钟。专项规划中的新增语义仍须确认，不因预留扩展空间直接实施。

先查现有 `summon_warden_bt`、Query 和技能槽，当前已有攻击/接近/无敌人跟随组合。主人指令、拴链、反击等若不能由既有能力表达，先界定新事实、意图优先级、失效与恢复，不写宠物专用大节点。

验证请求身份、延迟派生序号、重复请求、失败补偿、跟随/战斗交接和最终 source/retain/Brain 清理。不能只看召唤物数量。

### Motion

区分输入意图、运动源、仲裁、碰撞解算、实际位置和结果 Trigger。请求终点不等于碰撞终点；先写实际位置，再按既有合同处理碰撞效果，避免覆盖回调创建的新源。

分别核对自主移动、主动位移和对敌强制位移的门禁；穿墙途中扫描和终点修正；组间抑制；来源计时及撤销。Blink 当前为瞬时路径，不套用 Dash 的持续生命周期。

新的 Motion 模板、覆盖规则、控制免疫或仲裁语义须先提案。现有 Action 参数仍是当前编辑入口时，不能先写新表再当迁移已批准。

## 5. 复杂需求与规模增长审查

涉及同帧连锁、多来源冲突、部分失败、扩展包演进或批量交付时，参考 [战斗流程规模化复核](../../../../Docs/MobaCombatWorkflowScalabilityReview.md)。按受影响范围补充，不要求普通数值修改完整填写：

| 审查点 | 要得到的答案 |
|---|---|
| 结果语义 | 不变量是什么；何时采样；同帧先后和平局由哪个既有合同决定；正常/取消/死亡/替换怎样结束 |
| 失败与提交 | 哪个所有者宣布成功；允许部分成功吗；失败前的变更由谁补偿；提交后通知失败能否重试 |
| 重复身份 | 哪个 request/runtime/generation/事件键，在什么保留窗口内去重；网络重投与恢复后重演分别怎样处理 |
| 覆盖范围 | 哪些原语、相交边界和高风险长链受影响；关闭回滚/同会话恢复/所需网络与 Player 分别有什么证据 |
| 容量与版本 | 活动对象/未来任务/资格/历史保留有什么预算；内容、代码、扩展包与快照如何匹配；升级是否影响活动实例 |

易错边界：

- Trigger Sequence 拒绝后续动作不代表撤销此前效果；领域服务的局部补偿、按帧恢复、表现对账分开查证。不把整次 Cast 默认当作跨服务原子事务。
- Projectile/Area 派生结算预算不等于所有同步伤害/Trigger 递归均已受控；合法连锁资格与终止语义另查，不以预算超限作为正常玩法规则。
- 来源操作只有在合同声明可交换时才验证顺序无关；不能打乱共享 RNG、合法优先级或目标排序。时间边界查前一帧/当帧/后一帧。
- 当前权威 StateHash 主要覆盖 Actor 身份/Transform/HP 等；受影响的 RNG、资格、任务、来源等未来充分状态要另验，hash 相等不能证明完整恢复。
- 配置里声明 gate/CI 不等于实际执行。复用现有门禁，核对步骤、测试命中和结果文件；本轮查证的 CI 文件缺失是当前工作树事实，后续使用前重查。
- 交付证据关联实际源码（含 dirty 差异）、作者源与发布物版本、模式、场景/输入及结果；不把旧报告套到新的组合。先用现有报告记录，不先造通用治理平台。

已有原语的新组合核对这些边界后可按授权推进；发现新竞争、事务、版本或输出语义时，按机制治理提案。当前规范、批准方案、验收记录各维护自己的职责，Skill 不复制全部字段、历史计数或测试成绩。

## 6. 形成可审阅结果，再进入实现

普通接入输出受影响机制映射即可；跨机制分析额外给职责图、状态归属表、证据/差距和分批路线。复用仓库现有文档，避免创建相互竞争的规范。

每项归入 `规范内复用 / 待确认机制 / 已确认机制 / 既有违规待治理`。对待确认项，写明为什么现有组合不足、最小通用方案、可行替代、字段/接口与文件、兼容/生命周期/恢复影响和验收；不得先落入隐藏或关闭的实现。

已确认的范围继续有效，不因旧文档还写“待确认”而重复询问。无法核对时明确列出证据差异；不要自行把 Agent 推荐、测试通过或用户沉默记成批准。

建议优先使用现有高价值组合场景补验收：

- Projectile → Area → Motion：唯一提交、资格、实际位置、帧完成、来源释放。
- Summon → Brain → Cast/Move：身份、跟随/攻击交接、目标失效、终结和恢复。
- 长期模式 → 多次独立 Cast：本地状态/外部来源、槽位、提交前后打断及参数恢复。

验收按改动选择模块、生产组合、受影响英雄和发布检查。N 帧恢复后从 N+1 重演，检查未来所需状态与实际结果；同会话 journal 不替代重连基线。报告区分已运行结果、历史证据、仅源码入口和未覆盖范围。
