# 09 录制与协议演进

完成 01 后先运行离线录制；完成 03 的真实 State 联机后，再运行 Gateway 录制。Record/Replay 保存输入、权威快照和状态哈希，复演时从快照恢复同一份 `TinyBattle` 规则，并在记录了权威哈希的帧比较结果。

```powershell
dotnet run --project src/AbilityKit.Demo.Tiny.Record.Sample -- local/Logs/tiny-record.bin
dotnet run --project src/AbilityKit.Demo.Tiny.ProtocolEvolution.Sample
```

离线录制工程额外引用 `AbilityKit.Record`，使用 `FrameRecordBinaryCodec`，写入 40 帧输入、40 个版本为 1 的状态哈希和一份初始快照。读取时检查 WorldType、opcode、玩家、帧序、哈希版本与每帧哈希。命令行指定文件路径时保留录制文件；不指定时使用临时文件并在结束后删除。

`AbilityKit.Demo.Tiny.LiveRecord.Sample` 连接真实 Gateway，在 State 房间取得双端一致的权威快照，依次提交双方攻击与移动共六次输入，第二轮攻击等待冷却结束。Gateway 返回的接受帧是服务端调度帧；样例核对接受帧与下一状态帧的权威 HP 或坐标变化，再将生效帧写入 Record 输入。记录包含初始基线、第二和第四次行动后的两个中途快照、六次输入和实际收到的权威帧哈希；从三个快照分别复演，并在有权威哈希的帧比对。State 模式不保证每帧都有快照。短门禁 `./tools/verify-tiny-starter.ps1 -FocusChapter 09` 会启动服务端运行该样例，留下 `tiny-live-record.bin`、`tiny-live-record.json` 和日志。该练习验证短序列与中途恢复，不代表长局回放或跨版本录制文件兼容。

协议工程为练习定义独立封套：V1 为版本字节加当前三字节 `TinyInput`；V2 追加一个非战斗语义的提示字段。新版读取器同时接受 V1/V2，拒绝未来版本、截断和非法提示值。它还使用正式 Room 同步能力协商入口，检查 schema V1 可用、仅支持 V2 的服务端被 V1 客户端以 `SchemaVersionMismatch` 拒绝。正式 Tiny TCP 输入仍是三字节编码；练习不修改 `InputOpCode`、线上 wire schema 或 Room 兼容性基线。若将 V2 真正部署到联机协议，需先在协议目录定义新版本、执行生成与兼容检查，并同时更新服务端和客户端能力协商。

记录与协议演进各解决不同问题：前者验证同规则重放，后者验证旧数据能被新读取器解释。两者均不替代跨版本真实客户端与服务端的联机验收。
