# 08 跨层规则变更练习

**目标：** 在不改 Room、Gateway 或通用同步组件的前提下，将 Tiny 普通攻击伤害由 10 改为 12，并让规则、权威快照、三种同步模式和验收期望一起收敛。这是完成 07 后的维护练习，不是默认规则的变更。

## 修改路径

1. 在 `com.abilitykit.demo.tiny.logic/Runtime/Logic/TinyBattle.cs` 修改 `AttackDamage`。保持三字节 `TinyInput` 编码、`InputOpCode` 和 `TinyBattleStateCodec` 格式不变，因为本练习只改变规则常量。
2. 将 Logic 样例、服务端 `TinyBattleIntegrationTests`、客户端 State/Frame/Hybrid 验收中的目标生命值预期从 90 调整为 88。还要检查 `TinyProcessSmoke`、`verify-tiny-starter.ps1` 的双进程证据断言、`Tiny.Record.Sample` 的最终状态，以及 `Tiny.BattleStyles.Sample` 的两次命中结果（80 改为 76）。查找写死的生命值时按语义逐处判断，不批量替换无关测试数据。
3. 验证权威服务端和客户端都共编译同一份 Logic 源码；Frame/Hybrid 的回滚、哈希与周期快照必须基于新规则一致。State 客户端只读服务器快照，不自行推导伤害。
4. 运行 `dotnet run --project src/AbilityKit.Demo.Tiny.Logic.Sample`、Tiny 服务端定向测试、`dotnet run --project src/AbilityKit.Demo.Tiny.ChapterSamples`，再运行 09 的 Record 样例和 10 的战斗节奏样例，最后运行 `./tools/verify-tiny-starter.ps1 -SkipUnity`。预期两客户端和独立进程均观察到 88 HP，恢复后的完整快照仍为 88 HP，Frame/Hybrid 哈希与重放测试通过；检查 `process-State`、`process-Frame`、`process-Hybrid` 的证据文件。协议演进练习的封套格式不受本次伤害变更影响。

## 评判边界

本练习不需要新增 opcode、改 Room DTO、改 Starter 路由，也不需要把伤害计算复制到客户端 View。若规则与客户端/服务端不共源，Frame/Hybrid 的哈希或快照校验会失败；若只改规则未改验收，State TCP 断言会失败。记录这两种失败各自出现在哪个阶段，以及修正后的验收日志，才算完成练习。
