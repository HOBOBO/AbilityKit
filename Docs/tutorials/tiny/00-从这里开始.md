# 00 从这里开始

## 教程定位

本目录规定 Tiny 从纯规则到正式联机项目的学习路径。规则位于 `com.abilitykit.demo.tiny.logic`，联机实现位于 `com.abilitykit.demo.tiny`。章节示例只增加装配代码，不复制战斗规则、会话状态机或协议 DTO。每章指出新增依赖、项目职责、框架职责和可复查的结果。

01–06 均有可导入 UPM 样例，07 是完整项目装配入口。样例分为三个层级：可导入的 API 片段、可独立运行的 .NET 工程、正式 Unity 场景。03–06 的导入片段本身不是完整联机应用；联机与表现由 Tiny 包的正式实现负责。导入样例不改变包级依赖；只有 01 可仅安装 Logic 包运行。

## 学习路径

主线为 **01 规则 → 02 Room → 03 State → 07 项目装配**，先完成最小双人联机闭环。需要确定性帧同步时，从 02 进入 **04 Frame**；需要本地即时响应时，再从 04 进入 **05 Hybrid**。**06 恢复**是横切章节，在所选模式跑通后学习，不要求先学完所有模式。用 [08 跨层变更练习](08-跨层规则变更练习.md)检验接入是否可维护；之后按项目需要选学 [09 录制与协议演进](09-录制与协议演进.md)和 [10 战斗节奏变体](10-战斗节奏变体.md)。

02–06 安装完整 Tiny 包会拉入它声明的全部依赖，不能把 `Samples~` 的按需导入等同于按需安装依赖。

Tiny 对框架工具集采取按问题引入的顺序：01 故意只用纯规则与确定性哈希；02 引入 Network SDK、Room 和 Loading；03 使用权威快照、能力协商及 View 投影；04 才使用帧历史与回滚；05 在其上增加本地预测和周期快照校验；06 使用连接恢复、帧收件箱和全量快照游标；07 组合 Unity 场景与服务端玩法模块。技能、Buff、投射物、AI 和复杂编辑器工具属于 MOBA 等进阶示例，不应为了展示包数量而塞进 Tiny 的最小闭环。

`tools/verify-tiny-dependencies.ps1` 检查各独立工程的直接引用及 Tiny 包的依赖边界。09 的 Record 依赖只在可选 .NET 工程中；10 的回合规则以 `com.abilitykit.demo.tiny.turn` 为唯一源码，由 .NET Core 工程共编译。Turn 包单独安装，不改变 01–07 的主包安装成本。

进阶顺序为：09 先离线录制，再在 03 State 联机基础上录制真实 Gateway 权威帧，最后检查 Room schema 能力协商；10 先比较本地回合与实时规则，再运行 `tiny-turn` 双进程联机，最后进入可选 Unity 场景。原 Tiny 双人实时玩法已经提供最小 Arena 路径，不为展示玩法数量复制同质项目。09/10 的 .NET 网络验收在 `-SkipUnity` 下运行；完整验收额外运行隔离工程的无头 Unity 回合 PlayMode。

## 每章写作与验收规则

短门禁可运行 `./tools/verify-tiny-starter.ps1 -FocusChapter 01`（纯规则），或将章节号换成 `02`–`06`、`09`、`10`。网络章节会启动隔离端口的 Host/Gateway，只运行本章的 .NET 联机样例并保留 `phases.json` 与日志；短门禁不运行 Unity。07 的正式消费工程和双进程 Unity 验收使用完整 `./tools/verify-tiny-starter.ps1`。所有 Unity 验收均采用隔离工程、`-batchmode -nographics`，不截图。

每章说明前置章节、依赖、接入代码、项目与框架的职责、运行命令、预期结果、失败路径和正式源码位置。正文只展示本章新增的调用；完整错误处理保留在正式实现中。

可导入样例使用独立目录和命名空间，只引用公开 API；不得引用 `internal` 实现或复制 `Runtime` 源码。01 样例可用 `dotnet run --project src/AbilityKit.Demo.Tiny.Logic.Sample` 验收；02–05 分别由 `RoomSample`、`StateSample`、`FrameSample` 和 `HybridSample` 独立双客户端工程验收，04/05 同时运行各自的本地回滚样例；06 用 `ChapterSamples` 验收可导入片段，再用 `RecoverySample` 验收四类故障。

统一验收入口是仓库根目录的 `./tools/verify-tiny-starter.ps1`。它覆盖依赖层级、协议、.NET 测试、01 样例、02–05 独立双客户端工程、09–10 可选样例、三模式综合 TCP 与恢复，以及 Starter 和无 Starter 消费工程的隔离 Unity 批处理。TCP 阶段还为每种模式启动房主和访客两个独立 .NET 进程，并检查双 PID、房间绑定、攻击结果和访客恢复；证据位于当次 `local/Logs/tiny-acceptance-*/process-{Mode}`。`-SkipUnity` 跳过 Unity 批处理。PlayMode 断言项目入口、场景 Bootstrap、View 对象生命周期，以及 State、Frame、Hybrid 三种模式到角色对象的投影；独立网络 PlayMode 在同一隔离 Unity 进程内用两套正式会话连接真实 Gateway，验证三模式双端投影与访客恢复。完整门禁还为 Hybrid、Frame、State、Turn 各运行一对独立无头 Unity 进程，证据位于 `unity-cross-{Mode}`。无头测试不验证最终画面或两台 Unity 客户端的视觉交互。脱离源码仓库的客户端接入步骤见包内 `Documentation~/IntegrationGuide.md`；具体项目责任边界见 [Tiny 接入基线](../../design/09-ImplementationExamples/TinyStarterImplementation.md)。
