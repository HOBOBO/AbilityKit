# 05 混合同步

**目标：** 本地主控输入立即预测，随后由权威帧确认；周期完整快照校验历史状态并在失配时校正。

## 章节契约

- 前置：[04 帧同步与回滚](04-帧同步与回滚.md)。不为 Hybrid 另建规则包或第二套权威逻辑。
- 框架提供：帧历史、回滚、同步 Profile/Schema 协商与全量快照分发。
- 项目实现：预测范围、提交帧余量、输入确认后的表现、快照哈希不一致时的校正策略。
- 教学代码：对照相同输入在 Frame 与 Hybrid 下的客户端行为，只展示模式选择及本地预测调用。

## 验收与边界

导入 `05 Hybrid` 样例并运行 `TinyHybridExample.Run()`；它先预测本地攻击并确认，再重放迟到的远端输入。已有 Host/Gateway 时可运行 `dotnet run --project src/AbilityKit.Demo.Tiny.HybridSample -- 127.0.0.1 4058 my-run`。该工程先共编译并执行 UPM 本地样例，再经正式 `TinyBattleSession` 验证发送前本地预测与双端权威结果收敛；日志给出本地 `chapterHash`、权威帧号及预测/回滚计数。网络中的周期快照可先覆盖迟到帧，远端回滚由本地样例及复制器定向测试断言。统一门禁 `./tools/verify-tiny-starter.ps1 -SkipUnity` 将结果写入 `hybrid-sample.log`，并保留 `hybrid.log` 中的网络哈希收敛与 `session-hybrid.log` 的恢复验收。`Runtime/View/TinyBattleSession.cs` 在提交帧输入前调用 `TinyFrameReplication.PredictLocalInput`；`Runtime/View/Sync/TinyFrameReplication.cs` 负责权威帧和周期快照校正。

输入发送前本地状态应变化，收到权威帧后同帧哈希收敛；远端迟到输入触发重放，周期快照一致时保留后续预测，不一致时校正。隔离工程的无头 PlayMode 测试驱动正式会话与 `TinyActorViewModule`，断言本地攻击先更新现有角色对象的位置与 HP 高度，再由冲突的权威完整快照原位校正，且会话哈希回到权威状态。现有无头测试提供网络、规则和 Unity 对象投影证据；场景视觉证据仍待完成。

`./tools/verify-tiny-starter.ps1 -SkipUnity` 还运行 `session-hybrid-mismatch`：两名客户端使用正式 `TinyBattleSession` 和真实 Gateway；验收驱动只在本地向其中一端投递一次 HP 不一致的完整快照，并暂缓该端帧推送，让周期快照校正路径可稳定复现。断言校正一次且未触发全量恢复，然后用真实服务端快照核对双方同帧状态哈希。`local/Logs/tiny-acceptance-*/hybrid-mismatch.json` 保存预测帧和哈希、注入哈希、真实权威哈希、收敛帧、丢弃帧数及恢复请求数；该故障快照不是服务端产物。

当前 Hybrid 是**帧输入预测加周期状态快照**，不是通用“状态同步预测回滚”的完成证明。

Hybrid 的本地输入在发送前已经写入预测历史，因此服务端拒绝该帧时不会把同一预测直接改投到另一帧，而是暂停新输入并请求权威全量快照。发送等待期间的攻击短按由有界输入缓冲保留一次；请求失败的输入会报告错误，不会无限排队。
