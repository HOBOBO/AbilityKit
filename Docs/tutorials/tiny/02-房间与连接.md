# 02 房间与连接

**目标：** 两个独立客户端完成登录、创建/加入房间、准备和开战，项目代码只保留 Tiny 的房间策略。

## 章节契约

- 前置：[01 规则与确定性](01-规则与确定性.md)。导入本章样例需安装完整 `com.abilitykit.demo.tiny`，它会引入 Logic、Network、Room、Protocol、View 和 FrameSync 依赖。
- 框架提供：`RoomGatewayConnectionSession`、类型化 `IRoomGatewaySessionClient`、`RoomGatewaySessionFlow` 与连接恢复状态。
- 项目实现：账号来源、房间类型和标签、玩家槽位选择、进入战斗后的绑定；不得另写 TCP 帧格式、操作码分发或通用重连循环。
- 教学代码：只展示连接、创建/加入与阶段推进的调用链；登录凭据与取消令牌必须来自明确的生命周期所有者。

## 验收与边界

导入完整 Tiny 包的 `02 Room` 样例。`TinyRoomExample.CreateRoomAsync`、`JoinAndReadyAsync` 和 `StartBattleAsync` 接受已登录客户端的类型化 Room API、会话令牌及取消令牌，不保管登录凭据。独立工程 `src/AbilityKit.Demo.Tiny.RoomSample` 共编译这份样例源码，覆盖两个账号从登录、建房、准备、Loading 到开战的流程，不引入 State 快照处理。运行：

```powershell
./tools/verify-tiny-starter.ps1 -SkipUnity
```

检查 `room-sample.log`：两个账号应进入同一战斗，战斗快照包含双方玩家槽位；样例还用同一个建房命令 ID 重放一次请求，并断言得到同一房间。创建、加入或准备失败会抛出包含服务端消息的异常。正式场景会话位于 `TinyGatewayClient` 和 `TinyBattleSession`。本章尚无只安装 Network/Room 的独立 UPM 工程。

如果 Host/Gateway 已在本机运行，可单独执行 `dotnet run --project src/AbilityKit.Demo.Tiny.RoomSample -- 127.0.0.1 4058 my-run`。账号前缀应与其他运行实例不同；`verify-tiny-starter.ps1` 会自行启动隔离服务并运行该工程。

本章不介绍状态快照解析或帧回滚；连接成功也不等于已经获得战斗同步基线。

正式 Tiny 会话将启动请求的 `Timeout` 传给恢复、轮询与房间命令。超时表示客户端未收到结果，不表示服务端没有执行命令；重连时以恢复得到的 Room 快照为准。建房请求携带由调用方持有的命令 ID：同一次建房重试复用 ID 和同步模式，新的建房意图使用新 ID。`TinyRoomExample.CreateRoomAsync` 显式接收这个 ID；正式会话在待确认期间保存它。恢复到已有房间后不再重发建房；恢复为空房间时，用户可用原 ID 重试。连接失效时，场景会取消当前命令或轮询并优先恢复；旧回调不再更新当前界面操作状态。
