# 10 战斗节奏变体

完成 01 后先运行独立规则样例，比较两种项目节奏。完成 02–03 后可通过统一无头验收观察回合制的第二套服务端玩法：

```powershell
dotnet run --project src/AbilityKit.Demo.Tiny.BattleStyles.Sample
./tools/verify-tiny-starter.ps1 -FocusChapter 10
./tools/verify-tiny-starter.ps1 -SkipUnity
```

本地回合制分支一次只接收当前行动者的命令。越权命令不会改变状态；每次合法行动推进一个 Tick 并切换行动者。检查点同时保存战斗状态与下一位行动者，复演时比较组合哈希。

`com.abilitykit.demo.tiny.turn/Runtime/Logic` 是回合制状态、编码和哈希的唯一源码，`AbilityKit.Demo.Tiny.Turn.Core` 在 .NET 中共编译它。服务端通过 `TinyTurnGameplayModule` 注册 `tiny-turn` Room 与 State 同步模板，启动清单使用独立的 `tiny:turn.rules.v1` 键。`TinyTurn.StateSample` 的房主和访客是两个独立进程，连接同一 Gateway，验证建房加载、越权拒绝、访客重连、交替行动和胜者快照。网络帧继续推进，只有合法行动推进回合；`process-Turn/owner.json` 和 `guest.json` 留下验收证据。提交 ACK 仅表示排队，执行结果以权威快照确认。

可选 Turn 包另外提供 `TinyTurnProjectLaunch.Open`、`TinyTurnGameplayScene` 和 `TinyTurnSession`。项目传入已登录的 `DemoMultiplayerLaunchRequest` 与返回场景名后，可从场景创建/加入房间、准备、加载、行动并查看双方 HP 和胜者；会话使用 Room Loading、State 能力协商、全量快照游标和断线恢复。`./tools/create-tiny-validation-project.ps1 -IncludeTurn` 在隔离工程加入该包与场景。完整验收运行真实 Gateway 的无头 Unity PlayMode，留下 `tiny-turn-network.json`，覆盖行动、访客恢复和返回大厅。这个测试验证场景逻辑，不替代人工可视交互验收。

独立消费工程使用 `-Standalone -IncludeTurn`。`ConsumerTurnLobby` 的项目侧脚本调用 `TinyTurnProjectLaunch.Open`，真实 Gateway 用例留下 `tiny-consumer-turn-network.json`，证明项目大厅、Turn 场景与返回路径均可用。行动提交后的 ACK 只代表已接收；会话在权威快照推进前禁止再次行动，未知结果可用原命令序号重试。重建会话后若序号已被服务端去重，会有界续号，直到新行动获得有效 ACK。

## 跨层规则变更练习

在 `TinyTurnBattle` 将 `MaxHp` 从 2 改为 3，保持每次合法攻击扣 1 HP、房间人数和 State 同步模型不变。房主获胜应由第 3 回合推迟到第 5 回合。按以下顺序检查：

1. 修改 `com.abilitykit.demo.tiny.turn/Runtime/Logic/TinyTurnBattle.cs` 中的规则常量，并更新状态/编码测试与本地 `Tiny.BattleStyles.Sample` 预期；客户端和服务端必须共编译这份规则源码。24 字节快照格式无需改变。
2. 更新 `TinyTurn.StateSample` 的胜者和回合证据预期、真实 Gateway 用例与脚本中的三回合断言。确认越权行动仍不推进回合，合法行动每次只推进一个回合，重建会话后不会把去重 ACK 当作成功。
3. 运行 `./tools/verify-tiny-starter.ps1 -FocusTurnRecord -SkipUnity`，再运行不带 `-SkipUnity` 的定向无头门禁。检查 `process-Turn`、`tiny-turn-network.json` 和 `tiny-consumer-turn-network.json`。规则变更不应修改 Room/Gateway 通用合同；若修改状态编码，再单独评估 schema 与协议兼容性。

Arena 分支按固定 Tick 同时提交两名玩家的移动和攻击，连续推进 40 帧。在第 20 帧保存快照，恢复到第二实例后逐帧比较哈希；第 32 帧检查攻击冷却恢复后的再次命中。它展示实时输入调度的最小规则形态，未加入物理碰撞、更多玩家或在线匹配。

本地节奏对比样例引用实时 Logic 与可选 Turn Core；联机回合制独立复用 02–03 的 Room、同步与恢复能力，不增加原 Tiny Unity 包的依赖。原 Tiny 双人实时战斗已经覆盖最小 Arena 联机路径，因此当前没有再复制一套同质 Arena 服务端。未来只有在目标、结算或同步约束显著不同且有对应验收时，才值得增加新 Arena 变体。
