# 03 状态同步

**目标：** 把服务器权威快照映射到角色表现，明确客户端何时可以接受和展示状态。

## 章节契约

- 前置：[02 房间与连接](02-房间与连接.md)。目标仅增加快照订阅与表现所需的 View 能力，不复制网络协议。
- 框架提供：Room 状态订阅、生成的快照类型、同步能力协商与完整快照游标。
- 项目实现：Tiny 状态字段到角色视图的映射、对象创建/移除和可接受快照的校验。
- 教学代码：展示能力协商、订阅、等待完整基线，再读取同一权威帧中的两个角色；完整场景仍使用正式 `TinyActorViewModule`。

## 验收与边界

导入本包的 `03 State` 样例，通过 `TinyStateExample.RequireStateCapability`、`SubscribeAsync` 和 `ReadActor` 展示新增的协商、订阅与角色字段读取。运行 `./tools/verify-tiny-starter.ps1 -SkipUnity`，先查看 02 的 `room-sample.log`，再查看 `state-sample.log` 中的 `baseline=full`、相同权威帧及双端一致结果。`src/AbilityKit.Demo.Tiny.StateSample` 有独立入口，在 02 的房间流程上只增加 State 验收；`state.log` 与 `session-state.log` 继续覆盖包含恢复的综合路径。正式实现见 `Runtime/View/TinyBattleSession.cs` 的 `SubscribeAsync`、`TryGetNewSnapshot` 和 `Runtime/View/TinyViewModules.cs` 的 `TinyActorViewModule`。

重复、旧帧、其他 World 或非完整基线不得污染当前状态；相应游标与复制器契约由 .NET/Unity 测试覆盖。隔离工程的无头 PlayMode 测试还驱动正式 `TinyBattleSession` 和 `TinyActorViewModule`，断言完整快照创建两个角色对象、更新位置与 HP 高度、移除缺席角色，战斗绑定切换时在新基线到达前清理旧角色，并在模块卸载后清理对象。它验证的是会话状态到 Unity 对象的投影，不验证最终画面；两个可视化 Unity 客户端的场景验收仍待完成。

当前 State 模式**不做本地状态预测或状态回滚**。如果以后加入基于 `acceptedSeq` 的预测校正，应另加协议和测试，不能把 05 的帧预测当成这里已经具备的能力。
