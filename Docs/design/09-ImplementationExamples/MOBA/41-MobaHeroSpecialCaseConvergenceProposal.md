## 1. 目标与准入边界

保留 HFSM、短期 SkillPipeline、Trigger、Continuous/Modifier 和 Brain 的职责分工，把共享执行链中的英雄算法迁移为具有独立领域语义的能力；英雄只通过权威配置绑定这些能力。

本批只处理下列审计项及其直接依赖。具体英雄 ID、技能 ID 仍可用于内容绑定、资源映射、查询和验收，不能参与特殊算法分派。不得用新 profile、英雄组件、配置布尔值或换类保留原有特例。

依据 [机制准入规范](../../../MobaMechanismGovernance.md) 和 [技能开发规范](../../../../.claude/skills/moba-skill-authoring/SKILL.md)，本批计数投影、施法快照、瞄准策略和状态绑定语义已按上述确认记录授权。下文保留方案原文作为实施依据；原“待确认”标题不表示需要再次批准。超出 A–E 的新机制仍须单独提案确认。

## 3. 待确认方案 A：计数投影与 Cast 快照分离

### A1. Counter 只承担计数与显式投影

复用现有作用域、阈值、重置、后续 Trigger、来源撤销与同帧 HFSM 重评估能力。给已有 HFSM 投影增加显式线性变换：`parameter = sampledCounter * scale + offset`，默认 `scale=1, offset=0`。

- 保持现有采样阶段：未到阈值取递增后的值；到阈值取阈值值，存储值按既有 PreserveThreshold/ResetValue 规则处理。不得混淆投影值和实际存储值。
- 烬配置 `scale=1, offset=1`，由配置把 1..4 映射到 2..5；阈值、回调和清理仍由权威 Trigger 定义。运行时不认识弹匣容量或换弹槽。
- 变换参数必须有限；目标参数必须已声明且允许 Override。其他计数器默认保持原有行为。
- Counter 不再捕获攻击组、不查找最新 Cast，也不写入隐含的参数 12。

### A2. 当前动作组由准确的 Cast 持有

在 MOBA 技能契约增加显式参数快照绑定：来源参数 ID、目标参数 ID、采样阶段与所有权。第一批仅支持“施法准备时取得候选值，在该 Cast 的权威 Commit 点发布”；无须引入任意表达式或通用脚本。

- 成功选择本次技能时保留来源参数值；被拒绝的请求不发布贡献。Commit 幂等，读取本次选择时的值，不能读取已被下一发推进的当前参数。
- 发布到配置指定的目标参数，所有者为准确的 CastInstanceId/运行时句柄；事件链传递该身份，不用 `TryGetLatestRunning` 猜测。
- 完成、取消、打断、死亡和替换时撤销本 Cast 的贡献，旧 Cast 的清理不能删除新 Cast 的贡献。并行 Cast 按已有稳定优先级和来源顺序仲裁。
- 参数 10/12 只作为烬配置里的本地参数，不再被通用 ParameterService、SetParameter 或 HFSM 当作特殊全局角色。
- 失败补偿与回滚需覆盖已采样/未提交、已提交、已撤销三阶段；优先复用技能运行时和已有参数快照，确有新增字段时版本化处理，不能静默恢复成默认值。

替代方案是继续让 Counter 接管攻击组，或为每发硬编码一个流程。前者混淆计数和 Cast 生命周期，后者把耦合转移到执行分派，不采用。

## 4. 待确认方案 B：HFSM 通过声明绑定条件和状态职责

在项目侧增加 MOBA profile 配套绑定资源，和状态图同目录、同编辑器、同发布链管理，以 DefinitionId 显式关联；通用 HFSM 核心不加入英雄规则。绑定中只声明以下有限能力：

1. 参数比较、通用事实（存活、控制、当前 Cast/普攻）及 All/Any/Not 组合。已有参数比较语义保持；组合有节点/深度上限，不支持脚本。
2. 状态的 Cast 上下文策略：不携带、仅当前 Cast、同一状态实例内保留最后提交 Cast。明确关联的技能类别，不能让普攻快照屏蔽主动技能；状态退出或实例变化时结束保留。
3. 状态的瞄准快照作用域和捕获/保留/清理职责，供方案 C 消费。

换弹时长优先复用 `TransitionDefinition.MinimumActiveDurationRaw`，由 Authoring 配置逻辑持续时间，验证迁移后与既有帧边界一致。删除“换弹必须槽 5、75 帧”和“攻击组只有 1..4”的运行时代码；这些只留在该英雄状态图与数据中。

图校验应检查参数声明、条件引用、状态绑定唯一性和快照作用域，不能根据 profile 名称放行。通用 `active.skill.cast` 依据本次 Cast 的声明类别判断，不再隐式读取某个 profile 的参数 12。

生产图构造移出逻辑执行层；测试所需图由 fixture 或实际 Authoring 源加载。英雄资源使用统一的内容解析入口；迁移烬的旧资源名时同步编辑器、发布器和消费者，不在 runtime 新增英雄专属兼容算法。

## 5. 待确认方案 C：显式瞄准来源与作用域

施法契约声明 `Input` 或 `StateAimSnapshot` 两种来源，默认 Input。后者显式引用方案 B 声明的快照作用域。

- 在配置声明的进入边界捕获已解析的权威瞄准，作用域内后续短 Cast 消费同一份值；射击、重新进入瞄准子状态不能暗中重新采样。
- 退出作用域、控制中断、死亡或英雄替换时清理。重新进入产生新作用域实例，旧清理不得影响新实例。
- 快照缺失或已失效时明确拒绝需要它的 Cast，不悄悄退回最新输入。
- 目标查询、投射物、角色转向和表现读取同一次已解析请求。HUD 的普通 Release 快照基础能力保持原职责，不能代替长期模式快照。
- 快照和作用域身份参与回滚；重连未具备的覆盖应明确登记，不能只凭已有 HasFrozenAim 字段宣布闭环。

烬 R 配置为模式作用域内固定方向；其他技能默认继续消费输入。不增加识别 R、技能 ID 或槽 5 的逻辑。现有 R 固定方向、扇区选敌和射击顺序验收须保留；若查出当前行为与作用域契约冲突，先记录差异，不自行改变产品行为。

## 6. 待确认方案 D：由 Brain 配置产生飞行器意图

保留现有 BTree 驱动和选敌/选技能节点，增加两个独立领域节点：

- `MoveAlongLaunchHeading`：以生成时权威方向产生移动意图，受 CanMove 限制，明确世界/局部坐标转换；当前朝向变化不改变生成方向。
- `ResolveHeadingAim`：按指定方向来源及配置距离写瞄准点/方向；查询对象与锁定施法对象分开声明，不能把用于扫描的敌人自动变成使施法重新转向的 TargetActorId。

节点只读取 Actor/召唤生成上下文、行为树参数和既有运行时句柄，不读取英雄身份。前推距离由树配置（迁移时保持原有 16），选敌与炸弹技能仍走正式 SkillCast/Flow/Trigger。

`MobaBrainOutputApplySystem` 只应用意图，删除两处 SummonId 分支。生成方向若需独立保存，必须接入现有 Brain/Actor 快照；不得把未回滚的字典当权威状态。

状态机 Brain 的注册入口存在，但当前内建动作主要是投射物动作；不能据此认定已有完整的普通 Actor 移动/施法配置。本批使用现有 BTree，避免同时扩张另一套控制链。

## 7. 待确认方案 E：分离击退方向与距离力度

保持 Pull/Knockback 的方向解析职责。增加可选、显式的线性距离缩放参数：参考距离、近端倍率、远端倍率；未配置时倍率恒为 1。

公式为 `lerp(nearScale, farScale, clamp(distance / referenceDistance, 0, 1))`，距离在效果提交时按施法者/目标的 XZ 权威位置采样。参考距离必须正且有限，倍率必须非负且有限；缺少必需空间输入应按动作失败规则处理，不能静默改用某英雄默认公式。

只读解析当前 Trigger Source 后，`direction_mode=3` 的消费者包括嬴政 `10060211` 和鲁班 `10080211`，并非只有鲁班受影响。迁移时为这两个现有消费者显式配置参考距离 12、近端倍率 1.25、远端倍率 0.75，保持已有结果；以后未配置缩放的向外击退倍率为 1。若产品期望嬴政采用恒定力度，作为另外的行为修订确认，不在本批悄悄改变。普通 Pull/Knockup 和其他 DirectionMode 保持既有职责。Schema、编辑器动作描述和发布校验一起更新；不新增“鲁班击退”模式。
