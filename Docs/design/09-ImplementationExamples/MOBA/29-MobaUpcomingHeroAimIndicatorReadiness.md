# MOBA 后续英雄瞄准与指示器基线评估

> 状态：需求分析与基础能力准入建议，不代表后续英雄生产技能或 HUD 配置已建立。
> 范围：`08.Jinx_Arcanist`、`09.Veigar_Hextech`、`10.Gragas_StarGuardian`、`11.Karthus_Project`、`12.Lux_DarkStar`、`13.Jhin_Battlecast`、`14.Void_Annie` 七个资源目录。烬已有实现工作，本表将其作为现有样板候选，不视为待从零接入的英雄。
> 规则来源：技能的目标、命中和控制细节须在各英雄实现时按同一款目标游戏版本重新核准；下表用于发现交互形态，不是平衡数值或生产配置。

## 结论

应先把七名英雄的技能需求整理到可比较的契约矩阵，再决定是否扩展 HUD 点击与指示器基础配置。这里的“整理齐全”不要求先完成七篇逐阶段实现长文，也不要求提前冻结所有数值；最低要求是每个技能都标明输入模式、瞄准对象、预览几何、目标过滤/选择规则、释放时实际查询或碰撞形状、取消与反馈，以及哪些行为尚待版本核实。

原因是现有 HUD 已覆盖常见静态形状和按钮手势，但形状名不能表达命中规则。若现在先增加字段或枚举，很可能把某个英雄特例误做成共享配置；反过来若只按资源目录给技能随意分配形状，则容易得到“有指示器但预览和最终结果不一致”的假闭环。

实现优先范围已确定为上述七名拥有完整资源包的英雄，指示器和点击流程也随这些英雄的真实技能推进。Jhin 当前已有进行中的生产实现，应继续完成；首批 HUD 输入闭环选用 Jhin E（地面落点/Area）和 Jhin W（方向 Projectile），然后从 Jinx 开始推进其他英雄的机制闭环。鲁班等非目标英雄只保留已有通用基线，不再作为后续批次的实现样板。

以下按常见技能机制概括目标交互类型。技能正式语义、目标类别、命中次数、距离和视野等，仍以阶段 0 选定的目标版本为准。

| 英雄 | 技能形态初筛 | 现有形状可覆盖的部分 | 需求文档必须额外冻结的规则 |
|---|---|---|---|

| 古拉加斯 Gragas | Q 点选酒桶落点并延迟生效；W 自身蓄势；E 朝方向冲刺并与碰撞目标交互；R 点选爆炸位置并产生击退 | `TargetCircle`、`SelfCircle`、`DashLine` 可覆盖静态草图 | E 的实际可达终点受墙体和碰撞影响，直线预览不能承诺固定终点；R 的落点与爆炸半径、击退方向需分开表示；Q 的部署与二次引爆时机要区分。 |

| 拉克丝 Lux | Q 直线弹体且可能命中多个目标；W 往返直线；E 点选区域并可再次引爆；R 长直线激光 | `DirectionLine`、`TargetCircle`、`DirectionArea` | Q 的穿透数量与碰撞排序；W 往返阶段和角色移动时的路径；E 的布置/引爆两次输入状态；R 的长距离边界、宽度以及遮挡规则。 |
| 烬 Jhin | Q 点选目标/区域；W 直线射击；E 点选陷阱；R 持续瞄准扇区并逐发释放 | 已有 `TargetCircle`、`DirectionLine`、`Sector` 模板和表现消费测试 | 现有测试证明配置解析/形状存在，不单独证明触摸或鼠标手势、真实运行指示器、瞄准快照与命中几何一致。R 的输入跨多次独立射击，需继续遵循 HFSM/单次 Pipeline 边界。 |

## 当前点击与指示器基础判断

### 已有能力

- `SkillButtonTemplateMO` 已有长按时间、拖拽阈值、是否瞄准、方向/点选模式、UI 瞄准半径、世界指示器宽度、使用点模式和朝向选项。
- HUD 运行时枚举已有九种形状：`Hidden`、`DirectionLine`、`TargetCircle`、`SelfCircle`、`Sector`、`DirectionArea`、`DashLine`、`LockProjectile`、`FanArea`。
- 按钮已处理 Pointer Down/Drag/Up、长按进入瞄准、取消及预览句柄释放；数据模板可按技能解析成视图规格。
- 烬、孙尚香、鲁班已有模板语义验收；鲁班一技能还验证了指示器半径与实际 Area 半径及释放落点的一致性。这是静态点选 Area 的有限闭环证据。
- 目前鲁班一技能的几何验收由测试直接调用 `SkillCastCoordinator.TryCastBySlot`；它没有经过 `SkillButtonView` 的 PointerDown/Drag/Up、`BattleInputRuntime` 的瞄准投影和输入提交。因此已有测试证明“配置几何 → 权威 Area”一致，不证明“真实 HUD 手势 → 最终权威落点”闭环。

### 尚未证明或表达的能力

- 静态形状和模板解析不等于真实游戏运行闭环。仍需覆盖玩家手势、屏幕到世界的瞄准映射、最后一次输入快照、技能提交、失败反馈、取消和对象清理。
- 一些形状参数缺失时会由视图解析器使用默认值；模板 `IndicatorWorldWidth`、技能 `Range`、Area 半径、Projectile 碰撞宽度若来源不同，配置存在也可能产生几何漂移。
- 模板没有承载目标过滤/排序、遮挡、穿透次数、首个有效目标、无效目标状态反馈等完整瞄准语义。指示器外形无法代替实际 TargetQuery 或 Projectile 碰撞规则。
- 单个静态 preview 不能充分表现多实体部署（Jinx E）、反弹/往返（Lux W）、延迟区域（Veigar W/Jinx E）、可变冲刺终点（Gragas E）或长时间多次输入（Jhin R）。这类需求未必都需要新形状，但要定义预览阶段及提交快照。
- 当前配置契约的字段是表现模板字段。不要把目标过滤、伤害、提交时机等玩法权威写进 HUD 模板；若共享目标查询尚未存在，应由技能逻辑权威链复用同一参数/Query，视图仅消费预览结果。

因此当前基础可评为：**常见单次静态形状已具备接入起点；复杂目标语义和玩家交互闭环尚不足以宣称七英雄可直接铺量。** 暂无证据支持先批量增加新形状或给七名英雄填写模板。

## 需求矩阵必备字段

逐技能契约草案见 [30-MobaHeroAimInteractionMatrix.md](30-MobaHeroAimInteractionMatrix.md)。该矩阵已覆盖以下字段；不确定项继续标记为 `待版本核实`，不得把推测落成确定配置：

| 字段 | 要回答的问题 |
|---|---|
| `inputContract` | 点按、按住拖拽、长按瞄准、二次点击、方向键/摇杆，还是跨输入持续模式？Press/Hold/Release/Cancel 如何转移？ |
| `aimContract` | 方向、地面点、单位目标、中心点、冲刺向量或无瞄准？输入如何投影到世界/地面？ |
| `previewGeometry` | 预览形状及准确参数来自何处；是否需要多圈、多段路径、对象 ghost 或阶段动画？ |
| `targetContract` | 目标类别、候选过滤/排序、范围边缘、遮挡、穿透/首个命中和无效目标反馈是什么？ |
| `commitSnapshot` | Release/Commit 时冻结哪些方向、落点、目标、施法者位置和等级/数值？释放后输入是否还能更新？ |
| `executionGeometry` | 实际 Query、Projectile、Area、Dash 或召唤物使用的形状/碰撞参数是什么，如何和预览共享权威数据？ |
| `cleanupContract` | Cancel、失败、打断、死亡、切槽、冷却变化、回滚/重演时如何关闭指示器和预览 VFX？ |
| `evidence` | 哪个真实场景测试验证模板映射、玩家输入、瞄准快照与最终命中/部署几何一致？ |

## 指示器基础配置的准入顺序

1. **核准矩阵契约。** 确认目标游戏版本和资源目录；七名完整资源英雄是后续机制及指示器实现的优先范围，Jhin 当前在制并继续完成，Jinx 是后续首名新英雄。
2. **完成两种目标英雄闭环。** 先补 Jhin E 点地 Area 的 HUD 输入桥接，再验证 Jhin W 方向 Projectile 的输入更新、Release 快照和命中边界。两项已有生产配置和权威结果验收；欠缺的是经过 HUD 按钮和世界瞄准映射的完整证据。鲁班 Area 测试只作为非目标英雄的静态回归基线。
3. **拿缺口反推公共字段。** 若不同技能需要的字段能由当前 `SkillButtonTemplate` + Skill/Query/Projectile/Area 权威配置推导，就不加新字段；若字段确实缺失，再选择加到 Luban 权威模板、独立 TargetQuery/预览契约或视图输入配置，并同步 DTO、发布、解析、验证和测试。
4. **按契约扩展配置而非按英雄扩枚举。** 新增字段必须说明权威来源、单位、消费者、默认值/无效值、客户端与权威模拟关系、回滚是否需要，以及编辑器和发布校验。
5. **逐英雄形成正式实现文档和 fixture。** 到某英雄进入下一批时，再把矩阵展开成状态/参数、Pipeline、Trigger、Payload、表现和验收步骤；完成一个技能的输入、目标、结果、表现和清理闭环后再做同英雄下一技能。

## 当前推荐决策

逐技能交互矩阵已整理为 [30-MobaHeroAimInteractionMatrix.md](30-MobaHeroAimInteractionMatrix.md)，状态仍是待目标版本核准的交互草案。七名英雄的完整机制实现是当前业务优先级，HUD 输入和指示器应与每名英雄的实际技能一起交付；基础设施改动只由这些真实闭环的共同缺口驱动。Jhin 已有 E/W 生产技能及权威结果验收，下一步先在这两条真实技能链上补 HUD 输入：

1. **Jhin E 点地落点链。** 驱动真实 `SkillButtonView` Press/Drag/Release/Cancel，经 `BattleInputRuntime` 投影和命令提交；断言 Release 快照的世界落点等于陷阱 Area 中心，并覆盖取消、失败、延迟武装及对象清理。指示器若显示施法距离与陷阱作用半径，必须按两种不同几何验收，不能强行要求二者相等。
2. **Jhin W 方向弹道链。** 复用相同 HUD 输入路径，验证拖拽方向、射程裁剪、Release 冻结、线宽/预览和真实首个有效碰撞目标一致，并确认后方目标不受影响。
3. **按失败证据决定是否改模板。** 若现有 `SkillButtonTemplate`、Skill/Projectile/Area 权威数据能表达这两条真实英雄闭环，不增加 schema；若确有通用字段缺失，再按 `moba-skill-authoring` 的权威来源、发布和验证流程扩展，并同步运行时消费者与 Editor 校验。完成 Jhin 当前链路后，优先推进 Jinx，再按资源优先队列完善 Veigar、Gragas、Karthus、Lux 和 Annie；每名英雄都以单技能闭环交付。

每名英雄进入实现批次时，将矩阵条目展开成状态/参数、Pipeline、Trigger、Payload、表现、HUD 输入和运行验收契约。七英雄机制与指示器同批推进；共享 HUD 数据模型只根据这些英雄已经运行过的闭环演进。
