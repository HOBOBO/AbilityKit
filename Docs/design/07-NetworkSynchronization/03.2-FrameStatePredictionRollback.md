# 7.3.2 帧同步与状态同步预测回滚方案

> **文档类型：实施设计与现状审计**
>
> **事实基线：2026-09-16**
>
> **适用范围：** 业务逻辑状态、权威确认、客户端预测和恢复；View、插值与 Cue 的具体动作见 [表现重整](03.1-PredictionReconciliationDesign.md)。本文的“目标方案”不表示所有 Demo 已经接入。

## 1. 先选择权威事实

| 问题 | 帧同步（FrameSync） | 状态同步（StateSync） |
|---|---|---|
| 服务器确认什么 | 帧 `F` 的输入批次和可选的同帧状态哈希；服务端以这些输入推进权威世界。 | 帧/序列 `F` 的权威实体状态及其生效范围；输入仅用于客户端预测和服务器处理。 |
| 客户端本地保存什么 | 帧末世界快照 `S(F)`、逐帧输入批次、预测哈希和帧时钟。 | 本地受控对象的待确认命令及序列、可预测状态快照；远端对象保存权威插值样本。 |
| 发现不一致后回到哪里 | 若 `F` 的输入/哈希不同，恢复 `S(F-1)`，用确认的输入从 `F` 重新推进。 | **先应用权威 `A(F)`**，按 `acceptedSeq` 裁剪已确认本地命令，再重演未确认命令；无需让所有远端实体回到 `F-1`。 |
| 对比证据缺失 | 没有同帧预测哈希不等于一致；等待同帧数据或请求权威状态。 | 没有 `F` 的预测快照不能比较历史误差；仍可导入全量权威基线，但不能声称“校验一致”。 |
| 最小恢复粒度 | 一个确定性模拟 World 的全部未来相关状态。 | 本地受控实体的可预测状态 + 受其输入影响且可安全重演的局部对象；远端对象走权威快照与插值。 |

`RollbackCoordinator` 保存的是**本地世界**的历史状态，不会凭一个权威哈希构造权威实体快照。StateSync 的 `WorldStateSnapshot` 也只是通用元信息，不是 MOBA 全量业务实体协议。任何“按状态同步回滚”的实现都必须先定义可导入的业务权威数据、快照覆盖范围和输入确认语义。

## 2. 哪些可以预测

预测资格按**状态域和输入依赖**决定，而非按技能/实体名字开关。业务对象必须同时满足：输入归属明确；预测所需初态和规则完整；历史可独立复制；误差能比较；纠错不会重复发出不可撤销副作用。任何一项不成立，应仅做表现预览或等待权威结果。

| 状态或反馈 | 帧同步客户端 | 状态同步客户端 | 权威/回退规则 |
|---|---|---|---|
| 本地移动、朝向、无副作用位移 | 可在确定性规则及完整 Provider 下模拟。 | 优先预测本地受控实体的 pose/速度；重演待确认命令。 | 碰撞、控制效果、服务端位置不一致时覆盖逻辑 pose；View 平滑或重置由项目决定。 |
| 施法按键、起手、前摇、瞄准预览 | 可预测起手；真正是否合法仍需权威确认。 | 仅预测本地手感和可撤销的动作状态。 | 失败时取消预测动作；不要把起手当作命中确认。 |
| 本地冷却/充能与资源消耗 | 仅在配置、Buff、规则和恢复均闭环时预测逻辑。 | 可先显示待确认扣费/冷却，按权威槽位覆盖后重演。 | HUD 区分 pending 与 confirmed；拒绝施法必须返还预测值。 |
| 弹道、召唤体、区域对象 | 若生命周期、ID、索引、碰撞和外部状态全在快照内，可做有界逻辑预测。 | 默认只显示可撤销的本地临时对象；权威实体 ID/Spawn 决定最终实体。 | 预测对象使用临时身份与 generation；确认后映射，拒绝后删除，远端对象不做本地生成结算。 |
| 命中、伤害、死亡、Buff 层数、被动、随机效果 | 仅在完整确定性闭环及可重放副作用下可进入逻辑预测，默认不开放最终反馈。 | 默认**不预测最终结论**；可以显示标记为 pending 的低价值视觉反馈。 | 数值、目标、事件排序、随机种子和可见性由权威决定；飘字/音效必须能去重或撤销。 |
| 远端角色与 AOI 外对象 | 用权威输入同步推进逻辑，但不要以本地玩家输入推测远端操作。 | 权威快照插值；进入 AOI 时等待完整基线。 | AOI 缺失不是“实体已删除”；不拿局部可见集合做全世界回滚。 |

`PredictionStrategy.None/Optimistic/OptimisticWithRollback` 是处理器的策略标签，不是业务对象自动获得预测资格的证明。选型建议：高频本地主控可从移动开始，施法只预测可撤销起手，待相关状态和外部副作用测试通过后逐类扩大。

## 3. 帧同步：确认、快照与重演

1. 服务器和客户端先约定帧号、固定 Tick、输入批次内顺序及空输入帧。客户端在预测帧 `P` 提交输入后捕获 `S(P)`、哈希与该帧输入；容量必须覆盖 RTT、抖动、允许预测的最大超前帧及恢复等待。
2. 权威输入/哈希属于同一 World 和同一帧 `F`；只比较确定性字段。若输入不一致或同帧 hash mismatch，确认 `S(F-1)` 尚在，调用全部 Provider 的预校验，恢复其帧末状态。
3. 从 `F` 逐帧重演**权威输入**，包括同帧命令顺序和空输入帧；每帧重新捕获快照/hash。Host 的 `ClientPredictionDriverModule` 在 replay 缺少权威输入时等待，超时会禁用 reconcile；不能改用未确认本地输入冒充权威输入。
4. 对齐权威帧/hash 后才能发布成功的逻辑对账结果；回放失败、快照过期、导入失败或哈希仍不相符时停止该世界预测并走全量权威恢复。表现层丢弃恢复点之后的插值/Cue 历史，不直接修改权威战斗结果。

当前轻量 `ClientPredictionRunner` 的哈希触发路径直接恢复 `S(F)`，与上述 `S(F-1)` 语义不同；正式业务接入应以 Host 驱动的差异帧前一帧语义为准，不把两者混写成同一实现。服务端历史输入重演与客户端预测重演还需分别验收，不能以客户端测试替代服务器确定性测试。

### 3.1 MOBA Entitas 的已落地边界

[MobaRollbackRegistryBuilder](../../../Unity/Packages/com.abilitykit.demo.moba.runtime/Runtime/Application/Rollback/MobaRollbackRegistryBuilder.cs) 注册的 `10000` 实体 Provider 先保存 `ActorIdAllocator.NextId`、存活 `ActorId` 和 `SkillCastInstanceId`，恢复时从 ActorContext 清除预测期新增实体并同步解除 ActorRegistry/EntityManager 索引；召唤服务裁剪对应 owner/source/retain 索引。`10011` 运行时 Context Provider 保存 `ContextRegistry.NextEntityId` 和存活上下文 ID，清理预测期生成的上下文、实时 binding 及较新 snapshot，再回退自增 ID。`10018` 组件 Provider 保存当前缺少专项 Provider 的生命周期、召唤、弹道、技能 loadout/timeline 等组件存在性与字段；技能运行时数组逐元素重建，防止确认快照与预测帧共享引用。

其余 Transform/HP/资源、Buff timer、技能冷却/运行时、随机数、Blackboard、StateMachine/HFSM 等分别通过已有专项 Provider 恢复。注册表按 Key 升序导入，但**当前只实现了部分组件快照**，不是任意 Entitas `IComponent` 的递归深复制；Motion pipeline、AttributeGroup、Buff 实例、监听器和其它外部运行时对象必须由专项 Provider 或确定性重建负责。`GameContext` 当前没有状态组件，不能把它当作上下文 ID 游标；真实游标分别由 `ActorIdAllocator` 和运行时 `ContextRegistry` 管理。

预校验会拒绝“确认帧实体/上下文已被预测阶段真正销毁”的恢复；因为仅靠 ID 与局部组件无法重建其 Buff、索引、事件订阅和外部持有者。Flow ID/Phase、已删除确认上下文的快照及全部运行时副作用也**未**形成完整回滚契约。当前只能把这类失败转为全量权威恢复，不能宣称 Entitas 逻辑已覆盖所有复杂对象。

## 4. 状态同步：局部预测与权威覆盖

StateSync 的服务器周期性发送全量基线或具备明确基线 `B` 的增量 `A(F|B)`；包中至少要有 World/session generation、权威帧或序列、确认的输入序列/帧、对象身份、Create/Update/Remove、字段掩码、完整/增量标志和用于确定性局部对账的哈希。**AOI 不可见**必须与权威 Destroy 区分；增量不得在基线丢失时应用。

1. 本地发出不可变命令 `c(seq, inputFrame)`，本地主控预测并按序保存未确认命令及可预测槽位快照；远端实体独立存储权威插值样本。服务器确认 `acceptedSeq`/`acceptedFrame`，不要求所有端 Tick 结果完全相同。
2. 收到权威 `A(F)` 时先拒绝旧 generation、旧确认帧、错误 World、缺失增量基线和重复快照。按服务器确认序列裁掉 `<= acceptedSeq` 的命令，读取 `F` 的历史预测 pose/槽位比较误差；缺失历史时记录“不可比较”，仍以**完整权威状态**作新基线。
3. 将权威字段原子应用到本地主控及 AOI 内权威对象；服务器未发送的字段若属于可预测局部状态，需约定是“保持 pending”还是“由完整快照清除”。对不同生命周期的预测实体执行临时 ID 映射、撤销或清理，并重建可预测的外部索引。
4. 只重演 `> acceptedSeq` 的本地命令，依原顺序和原输入间隔推进到目标显示帧；重演期间不再次发送 RPC、触发最终伤害结算或重复外部 Cue。远端对象继续按权威快照插值，不参与本地主控历史重演。
5. 导入后按本地受控对象计算哈希/误差，刷新 pending HUD 和 View。误差过大、历史缺失、重复回退或耗时超预算时直接采用权威 pose，限制预测窗口或暂时关闭逻辑预测，等待下一全量基线。

这里的回滚是“**权威基线覆盖 + 待确认本地输入重演**”，不应复用 FrameSync 的整 World `S(F-1)` 恢复。逻辑复制策略可以复用 `IStateSlotValueCloner` 和业务 Provider 的字段编解码规则，但不能从预测 World 快照倒推出 AOI 外对象、最终伤害或服务端事件。全量快照用于断线/不可恢复重建；增量快照用于正常修正，两者不能混成同一导入规则。

### 4.1 当前 API 的真实能力与缺口

- [PredictionCoordinator](../../../Unity/Packages/com.abilitykit.world.statesync/Runtime/StateSync/Prediction/Core/PredictionCoordinator.cs) 处理本地玩家的逐帧输入历史、同帧批命令、槽位校验、权威覆盖和按原帧重演；`DictionarySnapshotStore.Record/Get` 都隔离副本，可变引用必须提供 `IStateSlotValueCloner`。它不处理 AOI、权威 Create/Destroy 或 View；命令实例在历史窗口内必须不可变。
- [ClientPredictionModule](../../../Unity/Packages/com.abilitykit.world.statesync/Runtime/StateSync/Client/ClientPredictionModule.cs) 有实体快照和本地主控预测，但 `Tick()` 把 `_confirmedFrame` 直接设为当前帧，`ApplyServerSnapshot()` 把 `_currentFrame` 设回服务器帧；[EntityPredictionState](../../../Unity/Packages/com.abilitykit.world.statesync/Runtime/StateSync/Client/EntityPredictionState.cs) 仅尝试恢复槽位并应用服务器实体状态，**没有待确认输入重演**。该模块不能直接宣称具备上述完整 StateSync 对账流水线。
- [ClientPredictionReconciliationCoordinator](../../../Unity/Packages/com.abilitykit.host.extension/Runtime/Client/FrameSync/ClientPredictionReconciliationCoordinator.cs) 已提供“权威快照之后裁剪输入 + 重演剩余命令 + 计算结果”能力；项目仍需接入业务权威 codec、acceptedSeq/帧映射、局部状态比较、实体生命周期及表现刷新。Shooter 专用 packed/recovery 实现不能自动推广到 MOBA 的 StateSync Profile。

## 5. 一致性、资源预算与降级

| 必需合同 | FrameSync | StateSync |
|---|---|---|
| 快照覆盖 | 所有影响未来模拟的组件、服务、ID 游标、随机数、外部索引和命令/事件历史。 | 本地主控可预测槽位、命令历史、权威可覆盖字段和预测临时对象；远端权威样本单独缓存。 |
| 引用与集合 | 每次捕获/恢复独立复制；不可序列化运行时对象需专项 Provider 或确定性重建。 | 槽位 cloner、权威 DTO 和读写快照都须独立复制，不能将网络 Buffer 直接存成历史引用。 |
| 确认与哈希 | 同帧、同 World 的权威输入和稳定排序状态哈希；哈希覆盖新增可预测领域。 | 同对象、同权威序列的局部字段比较；AOI 集合变化不能简单等同整世界哈希冲突。 |
| 回滚失败 | 预校验先于导入；Import 不是事务，失败后视为可能部分恢复。 | 不在丢基线时导入 delta；局部导入失败回到完整权威快照并清空 pending/预测临时对象。 |
| 副作用 | 重演时禁止重复网络发送、飘字、音效和不可撤销外部操作；事件身份要幂等。 | pending 效果与 confirmed 效果隔离；拒绝输入时能撤销预测效果，重演不能二次发 RPC。 |

预测窗口建议按 `ceil((RTT/2 + jitter + server snapshot interval) * tickRate)` 估算，再限定上限、历史字节预算和单次回放耗时。窗口、回滚历史、输入历史和权威基线缓存应按实测丢包及延迟留余量，而不是只用理想帧率计算。任一历史过期、World/session 切换、服务端拒绝输入、AOI 基线缺失或 hash 持续不一致，都需清空旧 generation 的预测轨道；当前项目应优先保证“停止预测仍能从权威全量快照恢复”，再开放复杂技能预测。

## 6. 实施与验收顺序

1. 为每个同步 Profile 明确服务器最终 commit 的模式、输入确认序列、权威全量/增量 schema 和可预测字段白名单；对未覆盖的对象默认权威驱动。
2. FrameSync 对每个 Provider 增加快照前后隔离、回退后确定性哈希和“预测 Spawn/Despawn + ID 复用”测试。补齐被真正删除的确认实体重建、Context Flow 和外部持有者前，不能扩大为任意 Entitas 组件预测。
3. StateSync 以本地主控 pose 建立 `A(F) -> trim -> replay` 最小业务链，验证 acceptedSeq、乱序/重复/旧 generation、delta 丢基线、AOI 进入/退出以及预测对象临时 ID 的撤销和确认。
4. 重放时校验命令不可变、同帧顺序、空输入帧、状态副本、RPC 不重复；View/Cue/插值验收按 [表现重整](03.1-PredictionReconciliationDesign.md) 分离。
5. 在 RTT/抖动、迟到输入、确认帧实体被销毁、回放超时和断线恢复下验证全量降级；分别保留纯逻辑 E3、真实双客户端 E4 和目标 CI gate E5 证据，不以局部测试宣称完整网络闭环。
