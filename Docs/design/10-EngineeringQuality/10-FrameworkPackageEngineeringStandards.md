# 框架包工程规范

> 文档类型：Canonical 工程规范。适用于 AbilityKit 自有框架包；2026-11-17 用户确认按阶段推进，并要求统一中文多行注释和整理明显临时代码。
>
> 本文规定工程实施要求，不自动授予任何包正式发布或新增机制的资格。成熟度沿用 [模块治理规范](04-CompanyAdoptionAndModuleGovernance.md)，发布流程沿用 [发布检查清单](06-BetaStabilizationAndReleaseChecklist.md)。

## 1. 适用范围与推进方式

所有自有框架包的 Runtime、Unity 适配和 Editor 源码采用本规范。第三方原始源码保留许可证和上游格式；生成源码应修改生成模板，不手工补注释。测试、示例和工具也使用中文说明，但不要求为每个测试方法重复添加 XML 文档。

统一目标分包落地：先完成 Core 试点，再按实际依赖顺序推广。尚未迁移的包必须标记为待整理，不能把规范已建立写成全仓已达标。新增和实质修改的自有代码按本规范执行，既有债务按包登记并逐批清理。

## 2. 职责与公开契约

每个包必须说明定位、负责与不负责的范围、直接依赖、源码入口、支持环境及当前限制。框架提供独立领域语义的机制；项目负责玩法策略、资源绑定、装配与配置组织。不得把项目特例改名后上移为框架机制。

公开 API 必须经过有意评审，并区分正式支持、实验和弃用兼容面。方法签名、默认值、排序、失败行为、所有权、线程安全、确定性和持久化格式都属于兼容性评审范围。保持签名并不意味着行为兼容。

Core 的新增准入继续遵循其包内 `CoreBoundary.md`，不得以“通用工具”名义扩大职责。涉及 MOBA 共享执行链的机制变化继续遵循 `Docs/MobaMechanismGovernance.md`。

声明完整状态操作或可选回滚支持的业务，职责与状态操作评审采用[业务状态与执行职责规范](12-BusinessStateAndExecutionBoundaries.md)。该规范统一状态、执行、所有者及适配边界，不要求所有业务实现公共接口，不将当前生成器的支持子集变成普通项目的写法禁令。

## 3. 源码与目录

- `Unity/Packages/com.abilitykit.<能力>/` 是包源码的权威来源，`.NET` 镜像工程通过显式源码引用复用，不复制第二套实现。
- `Runtime/` 存放运行时能力；依赖 Unity 引擎的适配必须有独立目录和 asmdef。纯 C# 程序集开启 `noEngineReferences`。
- `Editor/` 只承载编辑器能力，不能成为运行时依赖；资源、测试、示例和生成物边界应显式标明。
- 源码按能力与所有权组织。新目录不得使用缺乏职责说明的 `Temp`、`New`、`Utils`、`Common`、`Generic` 兜底。
- 同一能力的目录应统一命名；公开命名空间、程序集名和资源路径的调整单独评估兼容影响。移动 Unity 资产须同时移动原 `.meta`，保持 GUID。
- 文件以 UTF-8 保存，C# 缩进使用四个空格。优先一文件一个主要类型；紧密关联的窄职责值类型可以同文件，但应在文档中能定位。

## 4. 中文多行注释

框架代码注释统一使用中文，允许保留 API 名、协议词、公式等必要技术标识。不要通过给英文注释加“说明”前缀规避中文要求。

所有类型和对外可见的成员必须具有中文多行 XML 注释，包括接口成员、构造方法、运算符、枚举项、公开字段、Unity 条件编译 API 和保留的兼容代码。`summary` 开始标签、正文和结束标签分别占行；参数及返回说明可使用独立的 XML 行。实现说明使用中文多行块注释，避免英文注释和行尾说明。

```csharp
/// <summary>
/// 持有租用缓冲区，释放时最多归还一次。
/// </summary>
/// <remarks>
/// 已取得的视图在释放后失效；访问缓冲区不得与释放并发。
/// </remarks>
public sealed class ExampleOwner
{
    /*
     * 先撤销所有权再执行外部回调，防止回调重入时重复释放。
     */
}
```

注释描述真实行为，不能只复述名称或声称尚未验证的能力。按 API 实际情况说明：

| 情况 | 必须说明的契约 |
|---|---|
| 创建与销毁 | 所有者、释放时机、幂等性、释放后访问、失败后责任 |
| 集合与事件 | 排序、同值决胜、变更/枚举限制、重入、参数保留与回收 |
| 时间与数学 | 单位、范围、取整、零值和非法值、跨端确定性适用域 |
| 外部回调 | 执行线程/锁边界、异常传播或隔离、部分成功与补偿 |
| 热路径 | 复杂度与分配条件；性能结论必须引用可复现证据 |
| 兼容入口 | 保留原因、替代 API 和移除策略 |

实现注释解释算法、不变量和非直观取舍，不要求为每个私有字段或显然的赋值增加说明。既有 `inheritdoc` 可保留，但应同时写明本实现的中文摘要和行为差异。

## 5. 临时代码与实现清理

逐包检索 TODO、FIXME、HACK、临时/占位说明、重复文件、空实现、无条件成功、异常吞没、调试输出和一次性迁移入口。检索结果是审查线索，不能直接作为删除依据。

每项记录证据、真实调用方、所属契约和处置：

| 判定 | 处置 |
|---|---|
| 无使用方的私有残留、不可达分支、重复局部计算 | 核对调用和编译边界后删除或合并，保持行为 |
| 正式契约需要的失败兜底或异常隔离 | 保留并明确原因、失败结果和适用边界 |
| 已弃用但仍承诺保留的公开 API | 补齐注释与迁移说明，禁止新增使用方，不擅自删除 |
| 重复但存在语义差异的实现 | 先列差异；不能只因代码相似就合并 |
| 占位功能、契约冲突或需要改变机制 | 列为发布缺口并提出方案，按适用治理规则确认后实施 |

禁止通过放宽校验、扩大白名单、吞掉测试失败、重生成已发布 API 基线或删除行为断言使整理“变绿”。临时调试脚本、日志、截图和迁移产物不进入正式包。

## 6. 文档的权威来源

文档制度、写作模板、核校状态和迁移验收统一见[文档体系与维护规范](20-DocumentationSystemStandard.md)。本节只保留框架包工程的归属摘要。

按**读者和契约所有权**定位置，不按文件名是否含“设计”或“说明”判断：

| 位置 | 谁阅读、回答什么 |
| --- | --- |
| 包根 `README.md` | 包消费者：这个包做什么、怎样安装、最小接入和文档入口。版本和依赖以 `package.json` 为准。 |
| 包内 `Documentation~/` | 包消费者：公开 API、局部生命周期与资源所有权、限制、迁移和示例索引。为正确使用 API 所需的局部设计可以随包保留。 |
| 仓库 `Docs/design/` | 框架维护者及集成者：跨包分工、装配和执行链、全局约束、架构取舍及验证证据。 |
| 仓库 `Docs/` 其他目录 | 仓库用户：跨包接入教程、发布与验收说明、领域规范或历史资料。历史事实不得当作当前契约。 |

随包文档应能在独立安装后阅读，本地相对链接不得依赖仓库或兄弟包的目录布局；需要跨包导航时从仓库索引链接到各包。一个规则只维护一份权威正文，其余入口仅提供必要摘要或导向。新建包文档使用 `Documentation~/`；既有 `Document/` 等目录先保留，按维护规范核对消费者再迁移。对已整理的包用 `tools/check_repo_structure.py --strict --package <包名>` 检查包内路径；该检查不证明 API 或正文事实正确。

`CHANGELOG.md` 按实际变更记录 API、行为、兼容性、迁移与验证；历史条目保留历史含义，新的变更写入 Unreleased。旧日期、测试数量和“生产级”措辞不能作为本次发布证据。

## 7. 自动检查与验收

采用以下层次，避免以格式检查替代行为验证：

1. 中文多行注释和 XML 文档检查：`tools/AbilityKit.PackageQuality`。语法树识别真实注释与公开声明，覆盖常规和 Unity Editor 条件编译。该工具不评估注释事实正确性，也不穷举所有编译符号。
2. 包级编译、公共 API 基线、直接契约测试和实际依赖边界检查。
3. 按改动范围运行跨包回归与真实 Unity 编译/平台验证。
4. 从干净消费项目验证安装依赖闭包、最小调用、升级和回退，再进入发布候选评审。

新代码原则上无新增警告。既有债务应有范围、原因和退出条件，优先在目标包单独收紧，不突然改变所有包的警告策略。注释补齐后，目标包的缺失/损坏 XML 文档警告升级为错误。

### 发布准备与提交后验收

- **提交前**：允许从工作区验证候选。按包记录支持范围、依赖闭包、检查结果和未覆盖项；归档用于消费验证的源码清单与制品哈希。不要求为了验证单独提交，也不暂存或夹带未评审改动。普通 dry-run 可检查声明，工作区快照和声明预览均不代表通过正式发布门禁。
- **提交后**：由操作者确认最终批次，从实际待发布提交执行[严格输入预览](../../../tools/publish/README.md#提交内容一致性与证据)，核对所选包与依赖的输入身份。若提交内容与已验收候选不同，重做受影响的验证；计划发布渠道的依赖解析和正式签核仍须独立完成。未签核保持 `candidate`，不打标签。

## 8. 单包交付清单

- [ ] 职责、依赖、公开/实验/弃用边界已核对。
- [ ] 类型与公开成员中文多行注释齐全，注释与实现一致。
- [ ] 临时代码审查记录包含证据和处置结果。
- [ ] 目录、程序集与 `.NET` 源码复用边界清晰。
- [ ] README、包内契约、CHANGELOG 与设计索引一致。
- [ ] 对应检查和行为测试通过，报告记录实际命令与结果。
- [ ] 支持环境和未覆盖项明确，独立消费验证通过。
- [ ] 发布记录绑定可复现源码版本和依赖闭包；失败有回退路径。
