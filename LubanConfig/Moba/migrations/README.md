# 一次性配置迁移脚本

本目录保存此前将 JSON、旧工作簿和编辑器数据迁入 `Production/` 时使用的脚本，供追溯迁移映射。它们可能直接修改生产工作簿，日常配置维护不运行这些脚本。

生产配置以 `Production/Datas/` 为编辑源，导出只使用上一级的 `export_pipeline.py`。重复迁移前应先检查脚本目标、当前工作簿结构和工作树差异；历史脚本不保证适用于后续新增的列。

本地历史英雄接入脚本如需复现，应在可丢弃的隔离副本中执行。Karthus、Lux、Gragas 脚本的报告输入用 `--resource-facts <本次 Unity Inspect 输出的 JSON 文件>` 显式指定，不读取固定旧报告；只想核对参数时使用 `--help`。三者和复用它们的其他历史脚本不属于正式发布链。

新增的一次性读表探针和临时修补不要放在这里，按[仓库结构治理](../../../.claude/skills/repo-structure-governance/SKILL.md)放到被 Git 忽略的 `local/tools/<主题>/`。整理历史脚本时先核对同目录导入、本地调用和文档引用，不拆开仍被复用的脚本。

历史计划中记录的脚本名说明当时的变更来源，不等于现行工具入口。不要通过批量导入或执行脚本判断能否退役；有些入口经共享辅助函数写入生产表或作者源。按依赖组确认消费者和写入范围，再决定是否归档。

特效表现模板的 `PlacementSpace`、`TargetLossPolicy`、`CompletionPolicy`、`StopGraceMs` 已由生产工作簿和正式导出校验承接。日常维护直接改现有字段，不再运行历史加列脚本。

通用施法移动／转向约束以 [标签配置说明](../../../Docs/MobaTagAuthoring.md) 和生产标签表为准；通用目标查询的 `Rules.UnitSubType` 由技能表和 Luban 类型定义承接。日常改表不需重跑初始化或加列脚本。
