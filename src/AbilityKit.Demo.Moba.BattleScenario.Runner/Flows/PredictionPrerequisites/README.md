# 七英雄状态同步预测回滚样例

## 现在可播放：古拉加斯 E → Q 对照

在「Window → AbilityKit → 战斗测试用例编辑器」的左侧用例库刷新并搜索 `prediction-prerequisite`，分别选择「古拉加斯 E 命中维迦，接 Q」和「古拉加斯 E 落空，接 Q」。点「技能预览」观看正式技能，或点「运行断言」检查真实世界 Trace。

两份用例使用同样的种子、施法输入和技能时序，唯一的战斗输入差别是维迦的初始横向位置。E 命中版断言正好一次 E 伤害，落空版断言没有 E 伤害；两个版本均断言 Q 生成一次酒桶区域并执行一次二段施法。它们是正式技能和站位的对照，**不是状态同步录制**。不能将两局的 `SkillCast` 或表现剪接当成一次回滚的证据。

## 推荐样例组合

| 顺序 | 正式技能组合 | 回放中的辨识点 | 当前边界 |
| --- | --- | --- | --- |
| 1 | 古拉加斯 E 命中／落空维迦，接 Q | 同一 E 输入的位移终点不同，观察旧预测、权威落点、未终结移动重演。Q 和二段引爆可作为权威表现参照 | 正式技能配方和本地状态同步对账已接好；不重演伤害或 Q 状态 |
| 2 | 卡尔萨斯 W + 金克丝走位与 W | 墙可穿过，减速使同一走位输入的终点不同；区分普通位置纠偏和被硬控截断 | 先使用正式墙与减速；金克丝 W 的弹体和伤害只看权威结果 |
| 3 | 维迦 E + 古拉加斯 E；拉克丝 Q + 目标走位 | 对比跨边界、弹体命中后受控与未命中；确认后不重演受控前的过期移动 | 需先核对本地主控的控制态、运动终结和输入取消是否具备可恢复契约 |
| 4 | 烬 Q → W；拉克丝 E → 二段引爆 | 验证标记或槽位已被权威确认后才出现禁锢或二段；纠正后只保留一份施法／引爆提示 | 先做表现确认和去重；不预测标记、伤害、Buff 或 Area 生命周期 |
| 5 | 安妮 R → E（对提伯斯） | 比较权威召唤的出现、护盾目标和退场，校验迟到交付不会重复创建或留下幽灵对象 | 先保持召唤实体为纯权威；不预创建可参与战斗的临时召唤物 |

这些组合用于分开显示位置、控制、表现和对象生命周期，不要求七个英雄同场。组合技能的状态同步验收尚未接入；金克丝 W 已单独覆盖下述弹体表现契约。

## 本地验收：金克丝 W 弹体表现对账

`MobaLocalProjectilePresentationReconciliationTests` 复用正式 `jinx-w.battlescenario`。参考弹道与权威弹道由独立逻辑世界运行，通过只读投射物查询逐 Tick 采样。验收夹具把参考轨迹交给纯表现端口，以本地模拟结果驱动现有 Cue 对账器和实例注册表。拒绝分支显式交付拒绝结果，不把「没有观测到弹体」当作拒绝证明。

- **确认**：Tick 37 创建预测表现，Tick 38 更新轨迹，Tick 39 提升原句柄为确认态；重复确认不创建第二份。Tick 43 权威弹体退出时释放句柄，迟到确认不使它复活。
- **拒绝**：Tick 39 立即移除预测表现，重复拒绝不重复释放；Tick 40–43 的后续预测更新不再创建实例。确认的权威场景恰好一次伤害，拒绝的权威场景没有弹体或伤害。

在战斗测试用例编辑器打开「状态同步复现样例 → 选样例 → MOBA · 金克丝 W 弹体」，选择「权威确认」或「权威拒绝」。使用「下一步」或「跳到 Tick」查看轨迹、表现句柄、对账动作和实例计数。灰色轨道是独立权威世界的位置观测；橙色是本地预测表现，青色是确认后表现。空位置不会沿用上一 Tick；Tick 39 是样例模拟交付时点，不是权威世界首次观测弹体的时点。

重录：`dotnet run --project src/AbilityKit.Demo.Moba.BattleScenario.Runner -- --statesync-jinx-presentation local/Logs/jinx-w-presentation`。Runner 与测试共用录制路径，每个分支录两次并确认一致后写出两个 `jinx-w-local-presentation.*.statesync-replay.json`。可用「导入验收…」直接打开；更新内置录制时只复制这两个 JSON 到 `Unity/Packages/com.abilitykit.battlescenario/Editor/ReplaySamples/`，保留 `.meta`。

此验证不在客户端预测或回滚逻辑投射物、碰撞、命中、伤害或控制，也不代表正式会话或 Unity 弹体渲染已接入。

## 已接入：古拉加斯 E 本地状态同步录制

在「状态同步复现样例 → 选样例 → MOBA · 古拉加斯 E」选择「权威命中 · 纠偏并重演移动」。播放或单步查看六帧：旧预测 `1.354` → 权威交付，对照旧预测与 Tick 60 的权威落点 `-2.000` → 候选回到权威起点 `-2.000` → 重演 Tick 61 到 `-2.110` → Tick 62 空 Tick 不变 → 交付检查点显示 Tick 62 的新预测。位置条以 1/1000 世界单位显示 Z 轴。勾选默认关闭的「3D 双投影对照（仅角色）」可在固定镜头观察正式模型：深灰是权威，原色是旧预测或重演候选；回退起点两者使用同一姿态，只画原色候选。没有姿态的投影不显示；没有模型资源或旧版一维录制仍可看位置和 Tick。权威确认、无终结证明、历史缺口三种变体交付后只显示权威，不补造重演。技能预览仍从左侧用例库单独打开；双投影不启动战斗、不重放动画或特效。

### 状态账本与边界

| 数据 | 权威归属与本地验收 |
| --- | --- |
| 位置、速度、步长 | 正式世界末帧的 Transform、MoveSpeed、固定步长。保留三维位置供对账，只在绘图时量化 Z。观察到技能运动源曾激活且已结束，两侧截面前一 Tick 均静止，限定同一 Actor 生命周期、可移动、无技能位移干预。 |
| 普通移动与终结证明 | 验收侧按 Tick 写入类型化移动意图，检查 `MoveInput` 与正式 `LocomotionMotionSource` 实际消费值。权威 Tick 60 只含已终结的停止输入 `#1`，独立于快照绑定证明；预测侧保留 Tick 61 输入 `#2`，Tick 62 证实采样结束且无输入。 |
| 对账与重演 | 类型化全量截面先通过 `ClientSnapshotSyncPipeline` 准入，再由 `LocalMovementReconciler` 消费证明和历史。只用正式世界方向的普通移动来源进行一次隔离空旷步进，与权威世界后续真实 Tick 对照。不是帧同步，也不恢复导航、碰撞或完整 Motion/控制状态。 |
| 技能和战斗结果 | 测试的一次执行中，由权威与预测参与者各自运行正式逻辑，回放直接取观察值，不拼接两份旧录制。Q、伤害、控制、Area、召唤不进入重演；正式断言与权威 Trace 另存。 |

### 本地会话：主控移动和解契约

`LocalStateSyncMovementHost` 直接使用 MOBA 的移动输入采样和运动步进 System。预测世界持续运行；收到类型化权威快照时，按快照 Tick 比较主控的位置、朝向和持续移动输入。权威截面先导入隔离世界，按独立的输入终结证明裁剪已处理输入，再按原计划 Tick 重演；空 Tick 仍按持续输入步进。只有完整重演结果才写回预测世界，之后的新输入仍由原预测世界处理。

`MobaLocalStateSyncMovementHostTests` 已加入 `Battle flow regression` 门禁。它用独立本地权威世界覆盖同 Tick 匹配、晚到纠偏、预测历史淘汰、缺终结证明及后续恢复。历史缺失时若输入记录仍完整，可以从权威截面重演；缺终结证明时暂停预测，只保留权威截面。此契约限单主控、固定步长和固定移速；不支持动态属性、碰撞、技能或完整世界恢复，不改既有技能录制或正式会话。

选择「状态同步复现样例 → 选样例 → MOBA · 本地主控移动 → 逐 Tick 纠偏与继续预测」，用「下一步 / 上一步」核对九个观测步骤。交付发生在 Tick 3，对照的是 **Tick 1** 已录下的预测，并不是交付前最后一帧。回到权威锚点后，Tick 2 执行输入 `#2`，Tick 3 没有新输入但继续按已生效方向移动，Tick 4 写回原预测世界后执行新的斜向输入 `#3`。可选的 3D 模型只用于显示，不参与世界装配。

同一菜单下的「缺终结证明暂停 · 新基线恢复」展示另一条路径：本地 Tick 2 收到 Tick 1 的快照，虽然快照可导入，但缺少终结证明，于是只显示权威停点，不丢弃输入 `#1`，也不提前执行 Tick 3 缓存的 `#2`。本地 Tick 4 收到 Tick 2 的新基线，终结 `#1`，重演 Tick 3 的 `#2` 和 Tick 4 的无新输入步，追平后在 Tick 5 继续预测 `#3`。新基线没有同 Tick 预测样本可比较，因此回放直接从权威锚点开始重演，不合成一帧旧预测。

重录使用同一个 Battle Scenario Runner：`dotnet run --project src/AbilityKit.Demo.Moba.BattleScenario.Runner -- --statesync-movement local/Logs/moba-movement-replay`。两种录制均与独立权威世界逐 Tick 比对，并通过重复性检查后写出 `moba-local-movement.corrected.statesync-replay.json` 和 `moba-local-movement.proof-recovery.statesync-replay.json`。播放器可直接「导入验收…」；更新内置样例时仅复制对应 JSON 到 `Unity/Packages/com.abilitykit.battlescenario/Editor/ReplaySamples/`，保留 `.meta`。

### 本地重录

```powershell
dotnet run --project src/AbilityKit.Demo.Moba.BattleScenario.Runner -- --statesync-gragas local/Logs/gragas-statesync
```

该命令双跑比对录制和证据，通过后写出四份 `*.statesync-replay.json`、权威 Trace 及观测摘要。可用「导入验收…」查看新文件。正式资源改动需要更新内置样例时，只复制四份通过验收的回放到 `Unity/Packages/com.abilitykit.battlescenario/Editor/ReplaySamples/`，保留现有 `.meta`。本例不改生产接线，不启动网络服务，不读取网络载荷，也不检查项目外进程。
