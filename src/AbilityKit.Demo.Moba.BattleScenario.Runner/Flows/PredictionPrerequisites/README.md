# 七英雄状态同步预测回滚样例

## 默认演示：正式战斗候选

「Window → AbilityKit → 战斗测试用例编辑器 → 状态同步复现样例 → 选样例」按「施法与移动」及「逻辑弹体」分组。每套都从本地投递的已提交权威截面恢复到正式战斗候选世界，再按原 Tick 重演并在追平后发布。选中即自动预览；需要核查中间候选时切换「逐 Tick 检查」。不修改草稿，不接线上链路。

早期落点、减速纠偏和纯表现录制不再作为内置预设。已有录制仍可通过「导入验收…」只读查看，不能作为正式战斗预测恢复的证据。

## 现场运行：拉克丝 Q 发射前拒绝＋保留转向

在「战斗测试用例编辑器 → 状态同步复现样例 → 选样例」选择「拉克丝 Q · 发射前拒绝＋保留转向（本地）」。样例使用正式 Q（槽 1）与隔离移动，选中后现场运行并自动播放；需要时可切换逐 Tick 检查。

预测在 Tick 1 开始沿 X 移动，Tick 2 起手 Q。独立权威参考晚一 Tick 开始移动，不执行 Q。Tick 7 交付权威 Tick 3 的无在途施法截面并终结 `#2`，只在原 Tick 5 重演待终结的转向 `#3`。默认播放直接对比旧预测与发布姿态；逐 Tick 模式可确认 Tick 4 沿 X、Tick 5 转向 Z，以及 Tick 8 仍由同一候选推进。法力、Q 冷却和施法进度随和解纠正，深灰权威投影不随候选追平推进。

这是正式配方的**发射前拒绝**，拒绝由本地样例安排；不恢复在途施法、弹体、命中或伤害，不代表正式服务端的拒绝规则。

## 七英雄机制取舍

以本仓库当前发布的 `Resources/luban/moba/characters.json`、`skills.json`、正式 Flow 和现有能力验收为依据。下表列的是可用来区分展示目标的机制，不把有配置或定向测试等同于整套技能已支持状态同步恢复。

| 英雄 | 机制覆盖面 | 适合展示的组合与选择 |
| --- | --- | --- |
| 古拉加斯 | 被动回复；Q 酒桶部署/再施放；W 蓄力强化；E 碰撞停止；R 击退 | **首批选 E＋维迦站位。** 一个输入就能得到位置吻合或明显偏差。Q 再施放、R 击退适合后续对象或多角色恢复，不混进本次落点演示。 |
| 金克丝 | 被动击杀增益；Q 武器模式；W 直线弹体；E 陷阱；R 长程弹体 | **首批选 W。** 短时、单弹体、出现与撤销容易读；Q、E、R 会增加模式、区域或多目标结算依赖。 |
| 安妮 | 被动眩晕叠层；Q 指向弹体；W 扇形；E 护盾；R 召唤提伯斯 | W→E 已有输入确认/拒绝和资源验收，适合看日志，不如位移直观；R→E 留给召唤身份与护盾目标恢复。 |
| 维迦 | 被动成长；Q 多目标弹体；W 延迟落点；E 边界眩晕；R 终结 | **首批作为 E 的固定目标**，不主动施法。后续用维迦 E＋古拉加斯 E，验证碰撞截断与控制门禁；依赖可恢复的控制与运动终结。 |
| 卡尔萨斯 | 被动死亡施法；Q 延迟区域；W 可穿越减速墙；E 周期扣费；R 全局读条 | W＋金克丝走位最适合对比软控下同输入不同终点；需要墙、减速和有效移速的同次权威截面。E/R 与死亡模式留给专项。 |
| 拉克丝 | 被动标记；Q 弹体禁锢；W 往返护盾；E 区域/二段；R 延迟光束 | Q＋目标走位适合接在普通位移后展示“命中才控”，但先补弹体/控制资格。E 二段适合后续验证重施只结算一次。 |
| 烬 | 被动弹匣/换弹；Q 弹跳；W 标记禁锢；E 陷阱；R 架枪及逐发 | R 的几次独立射击最接近连续预测射击；首批不选，避免把弹匣、瞄准、子施法和弹体生命周期四类恢复混为一次演示。Q→W 可作为标记不抢在权威前展示的独立验收。 |

## 现在可播放：古拉加斯 E → Q 对照

在「Window → AbilityKit → 战斗测试用例编辑器」的左侧用例库刷新并搜索 `prediction-prerequisite`，分别选择「古拉加斯 E 命中维迦，接 Q」和「古拉加斯 E 落空，接 Q」。点「技能预览」观看正式技能，或点「运行断言」检查真实世界 Trace。

两份用例使用同样的种子、施法输入和技能时序，唯一的战斗输入差别是维迦的初始横向位置。E 命中版断言正好一次 E 伤害，落空版断言没有 E 伤害；两个版本均断言 Q 生成一次酒桶区域并执行一次二段施法。它们是正式技能和站位的对照，**不是状态同步录制**。不能将两局的 `SkillCast` 或表现剪接当成一次回滚的证据。

## 推荐样例组合

| 顺序 | 正式技能组合 | 回放中的辨识点 | 当前边界 |
| --- | --- | --- | --- |
| 1 | 古拉加斯 E 命中／落空维迦，接 Q | 同一 E 输入的位移终点不同，观察旧预测、权威落点、未终结移动重演。Q 和二段引爆可作为权威表现参照 | 正式技能配方和本地状态同步对账已接好；不重演伤害或 Q 状态 |
| 2 | 卡尔萨斯 W + 金克丝走位 | 墙可穿过，减速使同一走位输入的终点不同；区分普通位置纠偏和被硬控截断 | 正式墙与减速用于双世界对照；墙和减益结束后才交付普通移动截面，不接金克丝 W、命中或伤害 |
| 3 | 维迦 E + 古拉加斯 E；拉克丝 Q + 目标走位 | 对比跨边界、弹体命中后受控与未命中；确认后不重演受控前的过期移动 | 需先核对本地主控的控制态、运动终结和输入取消是否具备可恢复契约 |
| 4 | 烬 Q → W；拉克丝 E → 二段引爆 | 验证标记或槽位已被权威确认后才出现禁锢或二段；纠正后只保留一份施法／引爆提示 | 先做表现确认和去重；不预测标记、伤害、Buff 或 Area 生命周期 |
| 5 | 安妮 R → E（对提伯斯） | 比较权威召唤的出现、护盾目标和退场，校验迟到交付不会重复创建或留下幽灵对象 | 先保持召唤实体为纯权威；不预创建可参与战斗的临时召唤物 |

这些组合用于分开显示位置、控制、表现和对象生命周期，不要求七个英雄同场。金克丝 W 单独覆盖下述弹体表现契约。

## 本地验收：卡尔萨斯 W 与金克丝走位

这是保留给回归测试的独立慢速与走位对照，不从正式预设菜单执行。

- 同种子、同走位输入，两次正式战斗世界运行只改变 W 的施放位置。穿墙侧不被截停，但因正式减益移速变低；走位输入相同，停止位置不同。
- 回放跳过等待墙和减益结束的空闲区间。Tick 242 交付 Tick 240 的权威普通移动基线和停止输入的终结证明；隔离候选复用正式移动 System，依次重演 Tick 241、242，验证各步等于独立权威世界后切换。Tick 243 验证新预测继续推进。
- 这不证明墙、活动 Buff 或动态移速能从快照恢复，也不使用帧同步检查点。前半段是实采对照，后半段才是类型化本地状态同步纠偏。

该录制的命令行入口已退役；`KarthusWallWalkReplayTests` 仍验证机制和录制的可重复性。

## 本地验收：金克丝 W 弹体表现对账

`MobaLocalProjectilePresentationReconciliationTests` 复用正式 `jinx-w.battlescenario`。参考弹道与权威弹道由独立逻辑世界运行，通过只读投射物查询逐 Tick 采样。验收夹具把参考轨迹交给纯表现端口，以本地模拟结果驱动现有 Cue 对账器和实例注册表。拒绝分支显式交付拒绝结果，不把「没有观测到弹体」当作拒绝证明。

- **确认**：Tick 37 创建预测表现，Tick 38 更新轨迹，Tick 39 提升原句柄为确认态；重复确认不创建第二份。Tick 43 权威弹体退出时释放句柄，迟到确认不使它复活。
- **拒绝**：Tick 39 立即移除预测表现，重复拒绝不重复释放；Tick 40–43 的后续预测更新不再创建实例。确认的权威场景恰好一次伤害，拒绝的权威场景没有弹体或伤害。

可通过「导入验收…」打开纯表现录制。逐 Tick 检查展示轨迹、表现句柄、对账动作和实例计数；Tick 39 是样例交付时点，不是权威首次观测到弹体的时点。

重录：`dotnet run --project src/AbilityKit.Demo.Moba.BattleScenario.Runner -- --statesync-jinx-presentation local/Logs/jinx-w-presentation`。Runner 与测试共用录制路径，每个分支录两次并确认一致后写出两个 `jinx-w-local-presentation.*.statesync-replay.json`。可用「导入验收…」直接打开；更新内置录制时只复制这两个 JSON 到 `Unity/Packages/com.abilitykit.battlescenario/Editor/ReplaySamples/`，保留 `.meta`。

此验证不在客户端预测或回滚逻辑投射物、碰撞、命中、伤害或控制，也不代表正式会话或 Unity 弹体渲染已接入。

## 已退役：仅普通移动纠偏

原 `--statesync-gragas`、`--statesync-movement`、`--statesync-karthus-wall` 录制入口不再提供。走位和技能的正式演示使用编辑器的战斗候选世界配方，不把旧路线的位移写回作为替代。`MobaLocalStateSyncMovementHostTests` 仍将简化宿主用于验证独立的移动对账契约；历史 JSON 夹具继续覆盖只读格式兼容性。

### 基础技能逻辑：安妮 W → E

用「导入验收…」打开安妮 W → E 的确认或拒绝录制；用「看和解」直接到 Tick 93 的交付。确认分支只显示同 Tick 对照和发布，拒绝分支可逐步看 Tick 63 的权威基线、Tick 64–93 的未发布候选及最终发布。面板分开显示权威参考、旧预测和候选或实际发布；Tick 90 标出 E 的原输入位置。切换同用例的录制可在对应 Tick 继续对照。

```powershell
$out = "local/Logs/moba-acceptance/$(Get-Date -Format yyyyMMdd-HHmmss)-annie-skill"
New-Item -ItemType Directory -Path $out -Force | Out-Null
dotnet run --no-restore --project src/AbilityKit.Demo.Moba.BattleScenario.Runner -- --statesync-annie-skill $out *> "$out/runner.log"
```

复用安妮 W、E 的正式配方，使用 `SkillInputEvent` 直接驱动本地逻辑。样例安排 W（序号 1）终结，E（序号 2）仍待确认；权威拒绝由配方控制，不表示正式服务端的拒绝规则。确认分支的同 Tick 字段匹配，保留旧预测，W 不重复结算。拒绝分支用同一配方重建未施法的隔离世界、核对权威截面，再按原 Tick 重演 E。只在追平后切换发布轨道，检查旧 W 的魔力消耗、冷却和伤害都已撤下，而 E 仅施放一次。

原有 `annie-w-e-local-skill.{confirmed,rejected}.json` 是诊断明细；新增的 `annie-w-e-local-skill.{confirmed,rejected}.statesync-replay.json` 可通过「导入验收…」打开。更新内置版本时只将这两份通过验收的 `*.statesync-replay.json` 复制到现有 `Editor/ReplaySamples/`，保留 `.meta`。魔力和生命值在文件中保留 Q32.32 原值、在面板中按实际单位展示；冷却为世界时钟的毫秒结束时刻。这是只读录制，不是正式技能快照格式，不涉及在途技能恢复、远端预测、线上结算或帧同步检查点。
