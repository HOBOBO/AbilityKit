# 预测回滚：状态归属与延迟任务

本文记录当前实现与建议试点，不新增公开契约。回滚是可选能力；普通运行不依赖快照或重绑。包负责通用触发和调度，宿主负责模拟帧、领域状态恢复、运行依赖装配及输出对账。

## 当前支持边界

`TriggerExecutionScheduler` 可以在帧边界捕获、预检并静默恢复进度。恢复删除快照之外的条目、恢复 ID 游标，并保留剩余定义原有的相对顺序；不会执行任务或补发历史玩法。目标必须来自**同会话的有效历史**，原任务定义必须仍在。仅有运行 ID 或进度字节不足以验证分支身份，也无法重建缺失的定义。MOBA 的宿主适配器保留窗口内的原定义，导出等待项及游标；不是通用的任务重建协议。

帧边界由调度器检查；内部 `TriggerExecutionProgressValidator` 只检查游标、进度字段和定义是否存在，不调用绑定或写入状态。恢复每次重新预检，调度器仍独占定义与进度写入，校验返回的保留名单不决定调度顺序。

## 状态账本

| 内容 | 当前权威归属及恢复覆盖 | 分离边界 |
| --- | --- | --- |
| 加载后的计划、节点与动作/函数定义 | 宿主装配数据库和注册表；不随调度进度还原。 | 回滚窗口内使用同一版语义。若允许覆盖或重载，必须先明确计划版本和节点身份；不能仅凭数字 ID 找到任意同名定义。 |
| 执行树任务的进度、顺序与 ID | `TriggerExecutionScheduler` 保存等待/终态、计时、次数及分配游标；进度恢复复用原定义与其顺序。活跃计数由恢复后的条目计算。 | 继续由调度器持有权威进度；若未来支持重建，需保存能复现既有相对顺序的充分数据，不擅自改变同帧执行顺序。 |
| 执行树任务的描述与绑定 | 调度条目保存模式、间隔、上限、可中断性及 `Func<TriggerPlanExecutionResult>`；闭包捕获节点、参数和上下文。进度不保存这些内容。 | 候选任务描述保存可定位的节点身份、调度策略及未来执行需要的数据；处理器、服务和临时 Scope 不进入描述。 |
| 扁平计划的触发资格 | `PlannedTrigger` 保存 `Once`/`Repeat` 次数和 `Cooldown` 上次时间；另持有最近一次 `ExecCtx` 和可重建的绑定缓存。上述状态不在执行树调度快照中。 | 接入回滚前核对订阅的所有者、实例身份、时钟与资格恢复；同一计划 ID 的多个订阅不能共用一份次数。绑定缓存不代替资格状态。 |
| 扁平动作与业务定时规则 | `ActionScheduler` 的动作实例同时持有进度、回调和参数；`RuleScheduler` 按业务规则与效果对象推进。 | 仍由各自所有者管理；不能用执行树的进度恢复证明这两条链已支持回滚，也不在本试点迁移或合并。 |
| 领域值、身份、RNG 和外部输入 | 宿主负责世界状态、随机流和外部输入的捕获与重演。调度器只保存自身进度；引用可见的值不因此恢复。 | 从各自唯一权威所有者恢复或解析，不在任务内重复保存 RNG 或服务对象。已提交输出、表现与诊断按各自对账规则处理，不作为历史玩法回放。 |
| 订阅、索引、队列与帧内控制 | 绑定和索引是运行依赖；本进度快照不覆盖 `EventBus` 待派发事件或 `ExecutionControl`。 | 宿主需证明检查点处队列已结算，或独立为尚影响未来帧的输入建立恢复边界。只在读取前必然清理的值才可按帧内临时数据处理。 |

## 延迟任务上下文

当前 `ScheduledTriggerPlanExecutable` 将子节点、`args` 和 `ExecCtx` 交给调度器。`ExecCtx` 按值拷贝，`ExecPolicy` 的时间等值来自**安排时**；其中指向的宿主上下文、控制对象、注册表等引用没有深拷贝，`args` 也仍是传入的对象。因此延迟执行既不是完整冻结，也不等于在到期帧重新取上下文。恢复调度进度不会恢复这些对象。

后续试点应为每个输入显式选择时点，以下为提案而非已生效的行为：

| 输入 | 建议分类与需要确认的点 |
| --- | --- |
| 任务身份与计划节点 | 任务 ID 用于游标和实例关联；节点须由运行计划标识、节点键及可验证的版本定位。先验证覆盖、重复订阅和分支复用时的身份规则。 |
| 触发时载荷、来源与已作出的资格决策 | 仅保存后续仍需的确定性值及已定义的身份/代际；不深拷贝整个运行对象图。由具体消费者确认目标、位置、数值取事件时还是到期时；不把已冻结的资格重新评估一遍。 |
| 到期帧的服务和领域读取 | 由宿主在执行时按稳定身份解析。需要区分明确的对象缺失策略与非法检查点；不把旧引用替换成任意同 ID 的新实例。 |
| 时钟、随机与控制 | 先区分安排时策略值和执行帧时钟，明确读取/抽样时点及中断传播范围；不能在迁移时直接以新 `ExecCtx` 替换旧上下文，或复用上一次派发的可变控制对象。 |
| 处理器和输出 | 处理器可来自注册表并更新显式的宿主状态，但不依靠每个任务闭包隐存未来状态。恢复与重绑只校验或重建关系，不调用处理器；重演由正常帧推进产生输出。 |

## `Timed` 消费核对

按默认加载配置核对了 Unity/MOBA 的 `Resources/ability` 与 Console 的 `Configs/luban/ability`。两端的 `ability_trigger_plans.json` 和两份 `rules` 输入逐文件一致；各自的聚合有 280 条记录，其中 22 条带执行根。聚合与规则中均未发现 `Scheduled`、`Schedule`、`Timed`、`Periodic` 节点或 `ScheduleMode` 字段。受检源码中，显式把 `Timed` 提交到执行树调度链的调用来自测试。这个结论只覆盖受检资源与调用，不等于包外没有消费者；也不把扁平动作延迟、技能时间轴、持续规则或同名 UI 配置算作该机制。

目前可用的最接近生产装配的验证点是 `MobaPipelinePredictionReplayTests.cs` 中的 `In_flight_cast_replays_via_client_driver_and_formal_battle_registry`：它把三个 `ReplayProbeExecutable` 直接注册到真实的 `MobaTriggerExecutionRuntimeService`，由正式 `MobaTriggerExecutionTickSystem` 推进。探针不是已发布的触发器节点，不经过计划节点定位，也不代表技能处理器。

| 输入 | `Timed` 探针实际消费 | 对试点的约束 |
| --- | --- | --- |
| 延迟与顺序 | 安排时给定 50、50、90 毫秒；后续以 System 帧推进的 `deltaTimeMs` 累加，前两个同帧按注册顺序执行。 | 延迟和顺序属于任务数据；本轮不换算成帧数或绝对到期时间，不重排任务。 |
| 载荷、时钟与 Scope | 探针只把自身的整数标记写入测试记录；传入空载荷和默认 `ExecCtx`，不读取宿主、策略时钟、来源或 Scope。 | 探针可用按值的整数载荷替代对象内字段，但不能据此决定生产动作的目标、时钟或控制该冻结还是重取。 |
| 恢复依赖 | Provider 导入恢复进度与游标，仍要求原定义留存。测试比较逐帧 provider 载荷、执行顺序和战斗状态；缺失定义预检由 `MobaTriggerSchedulerRollbackPreflightTests` 单独验证。 | 继续作为正式 System 的兼容基线，不作为无闭包恢复已实现的证据。 |

## 试点收口与重绑定回归

早期试点验证了以值描述和调度器级共享派发器替代每任务闭包的可行性。复核后仍无真实消费者能明确哪些值应在安排时冻结、哪些值应在到期帧重取，因此移除发布运行时中的试点入口和派发分支，不新增兼容层或测试编译开关。公开 `Schedule` 沿用原回调及上下文绑定；公开 `RestoreProgress` 仍要求匹配的任务定义已存在。

`TimedExecutionRebindTests` 继续用**一个执行树 `Timed` 节点、一个固定注册的处理器、一个整数载荷**验证宿主重绑定。测试夹具单独保存计划版本、节点键、载荷与定义值；恢复时通过公开 `Schedule` 绑定新宿主的上下文，再调用 `RestoreProgress`。版本、节点、处理器或进度无效时，不替换夹具的活动调度器与定义账本，既有任务仍可执行。清空原调度器后，从同一检查点在两个新宿主上重演，逐帧比较同帧顺序、取消、次数、游标与宿主结果。

候选构建与发布只存在于测试夹具。回归证明宿主可以凭独立的定义值重绑定并静默恢复，不证明运行时已无闭包或生产快照可独立重建。测试节点不读取策略时钟、来源、随机或控制；没有替换 MOBA 探针或修改发布资源。

## 后续准入

1. **确认真实消费。** 从首个生产 `Timed` 节点列出实际载荷、时钟、来源、Scope 和控制对象的读取，以及身份失效及缺失策略。
2. **先确认契约，再评审接入。** 明确安排时冻结和到期帧读取的边界，再决定是否引入数据化派发或扩展生产快照；不由测试探针代定，不顺带迁移其它调度模式。
3. **保留行为基线。** 检查点 N 只恢复不派发，从 N+1 重演两次，逐帧比较；保留 `Periodic`、缺失定义拒绝、非法进度零写入及分配游标恢复回归。

.NET 回归类：`TriggerExecutionSchedulerRuntimeAccessTests`、`TimedExecutionRebindTests`。
