# World DI 使用契约与限制

从[包入口](../README.md)查看安装条件与最小用法。本包提供容器和装配接口；由宿主决定何时创建世界、推进逻辑和销毁世界。

## 生命周期与所有权

| 注册/接入方式 | 调用方需要保证 |
| --- | --- |
| `Singleton` | 实例属于根容器；不能依赖 `Scoped` 服务。跨世界共享同一根容器时不要存放只属于某个世界的状态。 |
| `Scoped` | 从 `WorldScope` 解析；每个作用域缓存自己的实例，作用域应先于根容器释放。 |
| `Transient` | 每次解析创建新实例，不进入容器或作用域的释放队列；调用方负责需要的 `OnDeinit` 与 `Dispose`。 |
| `CreateScope(seed => ...)` 或 `RegisterExternalInstance` | 传入的外部实例不移交释放责任；作用域播种的实例优先于同类型的注册。 |

容器不提供并发解析或释放保证。由宿主在约定的线程上完成构建、解析和释放。

释放根容器或作用域时，受管实例按登记顺序倒序退出，先调用 `OnDeinit` 再调用 `Dispose`。回调内再次释放同一所有者不会重复清理；回调可以读取已创建且尚未释放的依赖，不应在清理期间创建新服务。

## 世界管理器的所有权

- `IWorldFactory.Create` 尚未返回世界时，构造失败由工厂负责清理。返回新世界后，`WorldManager` 校验 `Id` 与请求一致，初始化成功才登记；失败会尝试释放该新实例一次。工厂误返回管理器已持有的实例时，拒绝且不释放该实例。
- 创建失败且补偿成功时，原创建异常直接传播；补偿也失败时，`AggregateException` 依次保留两个异常。世界实现必须能释放未初始化或部分初始化的实例。
- `Destroy` 先摘除指定世界再释放，直接传播释放异常。`DisposeAll` 先摘除当前已登记世界，再尝试释放全部快照成员；失败按世界 ID 标注后一起抛出。关闭期间拒绝创建，重入关闭直接返回；无论是否失败，关闭结束后管理器均可复用。
- 宿主关闭时，应在接住批量释放异常后继续清理非世界资源；若本次关闭用于补偿启动失败，应一并保留启动异常。管理器只支持同一宿主调度线程，尤其不要从 `Tick` 回调修改世界集合。

## 注册与解析

- 在组合边界用 `WorldContainerBuilder` 完成注册，`Build()` 后再解析。`IWorldModule.Configure` 负责注册，业务服务优先用构造函数注入，不在玩法逻辑深处查找容器。
- `Register` 可以替换同一服务类型的描述符，`TryRegister` 只在尚无注册时写入。多个模块共享同一类型时，要显式设计覆盖策略；见[模块组合示例](../Examples/02_ModulesAndComposition.md)。
- 必选依赖用 `Resolve`；真正有降级路径的可选依赖才用 `TryResolve`。根容器和作用域都传播循环依赖错误，其他创建异常仍可能折叠为 `false`。`false` 不等于“未注册”；排查问题时在同一解析边界用 `Resolve` 看原始异常。
- 循环检测以实际解析器和服务契约为边界。不同作用域可解析同一契约；若嵌套解析回到尚未完成的同一作用域和契约，仍会拒绝。

## 初始化失败与重试

受管 singleton 和 scoped 实例只有在 `OnInit` 成功后才会缓存并加入释放队列。初始化期间，另一个受管契约不能提前取得同一实例。失败不会触发自动重试、`OnDeinit` 或 `Dispose`，已经成功解析的其他依赖仍归原所有者。

再次显式解析会重新执行工厂；即使工厂返回相同实例，也必须重新通过 `OnInit`。工厂或初始化实现负责补偿失败的副作用；未确认实例可安全复用时，不要再次返回它。
