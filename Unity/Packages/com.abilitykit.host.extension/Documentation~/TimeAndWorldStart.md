# 时间与世界启动契约

| 能力 | 驱动与顺序 | 停止与失败 |
| --- | --- | --- |
| `FixedStepTickRunner` | 按累计宿主时间和倍率执行固定步长；`RunFrames` 显式推进，不消耗累计时间。 | 回调成功才计入帧号和逻辑时间。`Step` 回调失败时保留未完成的时间预算并传播原异常，不回滚回调产生的副作用。回调不得重入步进或重置。 |
| `ServerFrameTimeModule` | 创建世界前注册 `IFrameTime` 工厂。若安装时已有 `IFrameSyncDriverEvents`，只跟随 `PostStep`；否则按配置跟随宿主 `PostTick`。需要帧同步驱动时，应先安装驱动模块。 | 跳过帧守卫不允许提交的世界。卸载后停止驱动，不重置世界已持有的时钟。 |
| `TimerSchedulerModule` | 创建世界前注册 `IScheduler` 工厂，按宿主传入 `PostTick` 的增量推进，不提供确定性与回滚语义。 | 卸载后停止驱动，不接管世界容器的清理。回调应将世界集合的修改排到宿主 Tick 边界。 |
| `WorldAutoStartModule` | 帧尾从已登记世界查询 `IWorldAutoStartHandler`，处理器返回假时下次可以重试。 | 返回真后仅对同一世界实例停止重试；销毁通知、帧尾登记核对或卸载时清理失效记录。同 ID 重建不继承记录。模块不决定游戏的启动条件。 |

两个时间模块只注册工厂；实例归世界容器管理，不按世界 ID 保存候选实例。`TryGet` 和步进都只访问管理器仍登记的世界，并核对服务由本次安装提供。初始化失败的世界不可见，重复 ID 创建不会重置当前世界，同 ID 重建使用新实例。如果上层覆盖了服务注册，模块不会接管替代实例。

无论是正常销毁、释放时抛异常，还是直接调用 `WorldManager.DisposeAll`，已摘除的世界都不会再被时间模块查询或推进。这里只修复时间服务生命周期；不新增 Host 通知，也不改变既有的销毁事件与广播行为。关闭宿主时仍应卸载模块以解除回调订阅。

## 世界绑定与同步状态归属

| 状态 | 所有者与用途 | 失效边界 |
| --- | --- | --- |
| 自动启动完成记录 | `WorldAutoStartModule` 的运行期记录，不进入模拟快照；启动条件仍由世界的处理器决定。 | 只适用于当前登记实例，卸载清空。 |
| 服务端回滚上下文 | `ServerRollbackModule` 持有每个世界实例的输入历史、快照缓冲及捕获间隔计数；模拟状态仍由既有 Provider 捕获与恢复。 | 只登记本次安装期间经 Host 创建的世界；输入记录、捕获及恢复入口均复核登记实例，宿主帧初清理失效条目，卸载清空。重新安装不会给已有世界补建历史。 |
| 客户端预测上下文 | `ClientPredictionDriverModule` 持有逐世界的帧游标、输入与对账历史、回滚缓冲和恢复门槛；这些是预测驱动的运行期状态，模拟权威状态仍归世界及 Provider。 | 逐世界查询、重定基线、对账、推进和捕获均复核当前实例。帧初丢弃未收到销毁通知的旧上下文，不再调用其输入服务。同 ID 新世界建立自己的起始帧与历史。 |
| 帧同步会话 | `FrameSyncDriverModule` 持有待提交输入和帧包临时数据；宿主创建世界时绑定具体实例，调用方也可显式登记无世界会话。 | 已绑定会话失效后拒绝输入、停止提交和输出，不把待发输入迁给同 ID 新实例。有效的无世界会话不因缺少世界而清理；首次绑定时仍保留已入队输入。 |
| 世界与服务引用 | 世界管理器和世界容器持有并释放；模块只借用，不接管释放。 | 同 ID 新实例不得复用旧引用、历史或启动记录。 |

回滚仍按既有契约恢复帧末 N，并从 N+1 重演；本批不调整捕获时点、帧号、失败传播或同步协议。世界登记、宿主 Tick 和重演仍由同一驱动线程串行安排。
