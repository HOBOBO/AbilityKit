# 状态同步包接入契约

> 文档类型：使用指南
> 事实基线：2026-11-25；本轮重核本地 SnapshotBuffer、StateManager 及在线会话分层；其他预测/AOI 专题沿用现有说明，未全量重核。
> 核校状态：部分核校；本地测试不作为生产基线重建、世界导入或输入终结来源的证明。

## 接入路径

| 需要解决的问题 | 入口 | 不负责 |
| --- | --- | --- |
| 有界的本地帧历史 | `SnapshotBuffer`、`InputBuffer<TInput>` | 网络顺序、基线身份、权威输入确认 |
| 恢复存活实体的本地状态 | `StateManager`、`IRollbackable`、`IRollbackState` | 生成或销毁实体、推进世界时钟、重新执行输入 |
| 试验输入预测和重演 | `PredictionCoordinator` 与业务 `IPredictionHandler` | 在线会话、实体生命周期、表现插值 |
| 维护既有的实体槽位预测接入 | `ClientPredictionModule` 与 `IPredictableEntity` | 服务器输入确认、待确认输入重演、完整世界恢复 |
| 计算观察者单轮可见变化 | `AoiInterestSet` 与 `AoiInterestScope` | 业务世界恢复范围、实体寿命、发布预算 |
| 在线权威状态接收 | 项目会话适配层与 `com.abilitykit.network.runtime` 的准入能力 | 不要求安装 `StateManager`，也不依赖帧同步恢复游标 |

最小接线见 [包入口](../README.md) 和 [本地示例](../Samples~/LocalCheckpoints/README.md)。

## 本地历史与检查点

`SnapshotBuffer` 默认 128 个保留帧；容量不是帧号跨度或毫秒。快照存入和读出都复制，按升序列出保留帧号。`InputBuffer<TInput>` 默认同为 128 帧，但持有输入引用，调用方应保证历史窗口内命令不可变。两个缓冲均不解释帧号的业务含义。共享底层存储或跨多个调用的原子性由宿主负责。

在同一模拟执行线上注册实体、捕获、恢复与清理。`CaptureState` 捕获本次开始时已注册的对象；实体回调在管理器内部锁外运行。`TryRestore` 返回 `false` 表示缺少对应的世界快照或逐实体记录；返回 `true` 也只表示有检查点。没有当前注册、无法创建状态的实体会被跳过；恢复失败不会撤销已执行的回调。实体注销不清历史；切换世界或复用 ID 前须 `ClearHistory`，该方法保留注册。

`CaptureState` 写入缓冲的 `WorldStateSnapshot` 只包含帧和时间等元数据，逐实体恢复记录单独保存。因此 `GetFullState` / `ComputeDiff` 不是完整世界状态导出。不要外部覆盖同帧快照来替代捕获、也不要用这些本地记录替代帧同步检查点。

## 快照、差分及哈希

- `WorldStateSnapshot` 只承载可复制的框架元数据，默认版本为 `1`、`IsFullSnapshot` 为 `true`；全量标记不表示完整世界可恢复。业务扩展采用独立投影类型，通过宿主组合接入，不在其他程序集添加同名 `partial`。
- `StateDiffProvider` 在前态为空时生成全量，否则生成依赖前态的差分。`FromFrame` 和 `ToFrame` 在默认提供器的输出中均为 `0`；应用差分不验证会话、代际、权威帧或基线身份。调用方需保证基线、目标类型和提供器配置匹配；不把它接入现有固定基线的准入链。`ISnapshotPacker` 也是独立兼容面，不会自动连接网络。
- `StateHashComputer.Compute` 只组合版本、帧、时间戳和世界标志，不包含 `WorldId`、全量标记或业务状态。聚合业务哈希需要显式提供来源；哈希一致不等于状态完整、可恢复或可信。
- `StateHashValidator` 只作诊断：快照重载缺任一快照时返回通过，直接比较哈希时两个无效值也相等。只有快照重载遇到不一致才同步通知；需要严格对账的宿主应先检查样本是否齐全、有效以及双方是否指向同一状态口径，不用 `IsValid` 单独决定导入或恢复。

## 观察者可见集合

每个观察者维护独立的 `AoiInterestSet`，串行提交本轮完整候选列表。新键使用可见半径，已可见键使用边界半径，圆周纳入范围。可见半径为 `0` 时不做距离过滤；`MaxEntities` 和 `Priority` 当前不影响筛选或排序，宿主如需发布预算，须在适配层另行处理。

`Enter` 和 `Stay` 按样本顺序返回，随后按类别、标识升序补 `Leave`。调用方应对候选键去重；`forceFullBaseline` 先清除观察者历史，不为旧键补发离开。需留存时用 `Evaluate`；同一轮立即消费可用 `EvaluateTransient`，其结果会被下一次临时评估覆盖。可见、不可见或离开均不决定实体是否存在或可恢复，也不提交同步游标。

## 关键帧计划

`KeyFrameStrategy` 的构造默认间隔为 `60/10/3` 帧，重叠时按全量、主要差分、次要差分、增量的顺序分类。它不维护时钟、确认帧、可用快照或基线；查询到的只是计划帧，不能直接当作可回滚检查点。`EstimateBandwidth` 是每帧的粗略估算，不是实测带宽也不是每秒吞吐。

## 预测入口

- `PredictionCoordinator` 处理局部槽位；应用权威值时可按原始帧顺序重演保留输入。同帧多输入按记录顺序执行。自定义可变槽位应提供 `IStateSlotValueCloner` 保证历史隔离。默认值、兼容行为以源码中的 `PredictionCoordinatorBufferOptions` 为准。
- `InputHistory` 不区分空帧和已淘汰帧，两者都会产生空批次，宿主须保证权威帧到目标预测帧之间的历史确实可重演。成功应用的权威状态帧不等于输入已终结；处理器、直接事件订阅或复制策略失败时，不承诺恢复到调用前的状态。
- 正式对账前先定义权威值所对应的模拟 Tick、真实的输入终结与截断规则、实体代际以及回调失败策略。不能把状态快照帧、快照序号或帧同步确认直接解释为输入终结。

### 实体预测兼容入口

| 参数或开关 | 默认值与实际含义 |
| --- | --- |
| 输入容量、实体历史容量 | 默认配置分别为 `128`、`30` 个保留帧；`MaxPredictionFrames` 不是预测领先上限。传入显式缓冲选项后，使用选项容量。 |
| `EnableRollback` | 默认请求开启；构造参数可覆盖配置，且必须同时开启实体历史。关掉回滚不等于关掉历史记录。 |
| `SnapThreshold` | 默认 `0.1`，仅保留兼容字段，默认实体模块不读取该值。 |

由宿主在同一执行线上驱动。`SubmitInput` 按模块当前帧入缓存；`Tick(frame)` 只读该帧输入，只对本地控制实体预测，然后记录实体槽位、发布变化，并更新本地 `ConfirmedFrame`。权威快照按传入顺序应用，若较早校正帧的槽位历史命中，可先局部恢复，再由绑定实体应用权威快照并刷新预测槽位。此路径不验证待确认输入、不调用业务恢复接口进行完整世界回滚，也不重演后续输入。处理器与事件同步执行，异常不撤销已完成的变更；不要在回调中重入。实时槽位引用不适合被当作历史副本保留。

## 本地通知与诊断

| 入口 | 时机与含义 |
| --- | --- |
| 实体 `OnSlotChanged` / `OnRollback` | 槽位收集时同步通知值变化；较早的历史槽位真正恢复后通知实体回滚。实体回滚通知可能早于业务实体应用权威值。 |
| 模块 `OnRollback` / `OnSnapshotApplied` | 按快照数组顺序处理已登记实体；单实体校正成功后，若命中历史并确实回滚，先发回滚，再发快照应用通知。缺历史仍可应用权威快照并发出快照通知。 |
| 模块 `OnStateChanged` | 在 `Tick` 记录快照后、更新本地确认帧前发布待处理槽位变化；校正过程收集的变化也在这里发布，不保证跨实体顺序。 |

模块回滚的 `FromFrame` 取批开始前的模块当前帧，不是实体游标；快照通知使用校正方法的帧参数。`SnapshotAppliedEvent` 保留为兼容值类型，默认模块的通知仍传递实体标识和帧两个参数。槽位变化的新旧值不深拷贝；`IsPredicted == false` 也可能来自局部历史回滚，不能解释为服务端输入确认。

回调在调用线程同步执行。订阅方不要重入，也不要修改正在遍历的集合；回调异常向外传播，可中止后续通知或本批剩余实体，并保留已经应用的变更。快照应用通知不是整批提交确认：模块当前帧在整批完成后才更新；在线接收位置仍由会话适配层在成功导入后提交。

## 在线会话与分层

状态同步由适配层验证快照及基线、重建状态、导入世界，并在导入成功后提交接收位置。逻辑导入与表现消费可使用不同的投影范围。帧同步由权威输入推进并依照自身检查点恢复；两者可复用玩法世界、状态值及部分基础设施，但不能共用权威游标或互换恢复资格。

[稳定性评审](StabilityReview.md) 记录当前可用范围、兼容限制与尚未验证的发布条件。验证使用本仓库类型化对象和本地回归，不分析网络字节。
