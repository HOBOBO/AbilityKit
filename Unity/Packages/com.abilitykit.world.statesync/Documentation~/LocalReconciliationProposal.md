# 进程内状态对账方案（P0 已实施）

本文件细化局部移动预测的包内契约；跨包设计见源仓库的 `13-StateSyncReplicationAndPredictionProposal.md` 中的 D2。用户已确认 P0；首阶段只在本仓库以自有、类型化夹具构造权威状态与输入，不接线上、现有本地大厅或发布链。排查限定本项目源码与测试数据，不枚举、附加或检查本项目以外的进程、内存或运行时对象；不抓包、不读取或解析网络载荷、不访问外部服务。

## 职责与所有权

- **会话、复制准入与世界导入**：沿用现有固定基线职责。只有已成功导入并提交的权威移动投影，才可成为对账基点。对账器不接收未提交候选，也不修改快照基线、顺序、事件水位、请求策略或接收位置。
- **状态对账**：独立保存最近可信的权威移动投影、待终结输入及重演所需 Tick 的覆盖证明；对账结果是局部预测投影，不写回权威世界。复制提交位置、输入终结序号、预测 Tick 是三套状态；帧同步仍保留自己的时钟、确认与恢复资格。
- **业务适配**：提供本地受控实体的隔离移动状态和无副作用的步进。目标是复用业务固定步长与普通移动规则，不另写英雄行为。真正接入 MOBA 前要列出位置、速度、朝向、移动约束及环境依赖的权威来源、采样时机与可复制边界。动态碰撞、控制和受管位移缺任一可复算依赖时走权威。不预测远端、投射物、最终命中、技能、伤害、Buff 或资源结算。
- **表现**：首阶段由测试读取提交结果，不新增发布回调或大厅入口。后续接入时只消费最终投影，不监听重演内部 Tick；失败或作用域失效时撤销局部预测覆盖。已有远端插值保持不变。

## 输入终结与重演

1. **绑定唯一作用域。** 权威样本、终结证明和历史应关联同一个会话代际、世界、状态流、实体标识与实体生命周期标记、控制者和输入 epoch。标识复用、换世界/换流、控制权更替或会话重建不能沿用旧历史；旧作用域的输入和完成结果作废，不迁移到新实体。夹具显式赋值，真实接入不得用实体 ID 或推测代替生命周期来源。
2. **证明来自同一权威截面。** 样本以权威模拟 Tick `T` 完成后的移动投影为基点，和同一提交版本的连续终结水位一起交付。水位只能跨过状态效果已反映在该截面、或已明确终局拒绝的输入；接收、入队、临时失败和缺口不算终结。首阶段要求终结以序号前缀成立，且前缀之后没有已反映的移动效果；若真实执行允许高序号先影响状态，不能用连续水位掩盖，须另议稀疏结果或限制适用范围。相同 Tick 的更新须来自复制层已确认的新提交；重复版本、旧作用域或同作用域水位倒退不能裁剪历史。快照 ID、可靠事件水位、帧同步确认、`ClientPredictionModule.ConfirmedFrame` 均不能当作输入终结。
3. **验证覆盖后再重演。** 在已提交样本的有效终结水位下裁剪已终结输入，从 `T+1` 到目标预测 Tick 依次推进，显式保留无输入 Tick；同 Tick 按输入序号稳定处理。每一 Tick 必须能区分「确知无输入」和「记录缺失」，且具备约定的环境依赖。剩余输入原计划 Tick 不晚于 `T` 时，不丢弃、不挪到下一帧、不重演到基点前；首阶段关闭预测覆盖并保留待终结记录，等待后续权威信息。
4. **预测候选单独提交。** 在独立、可丢弃的投影内步进，不触发输入发送、Cue 或任何玩法结算。全部验证与重演成功后，才替换局部预测结果；命令及投影不得共享可被步进修改的权威引用。可信权威样本与有效终结水位不依赖重演成功；步进失败只丢弃预测候选，不撤销已提交的权威状态，也不重新排入已终结命令。

## 降级、基线与提议默认值

| 情况 | 建议处理 |
| --- | --- |
| 权威投影可信，但无同截面终结证明、输入过期未终结、覆盖不足、容量越界或步进失败 | 关闭预测覆盖，使用最近已提交的权威投影；没有有效证明就不裁剪输入。有有效证明时只裁已终结部分，其余仍保留。仅当后续权威样本使作用域、终结和覆盖条件重新成立时恢复预测；不因此标记固定基线失效或请求全量。 |
| 收到旧作用域、重复提交或迟到的候选结果 | 忽略，不改权威锚点、待终结输入和预测结果。显式切换作用域才废止旧缓存；新作用域从可信权威锚点开始。 |
| 当前作用域的固定基线确实失配，或权威导入失败 | 停止对此不可信世界使用旧预测覆盖，不接收失败候选作为权威锚点；交回现有会话全量恢复。以合法全量完成导入与提交为解除条件，不以请求返回或收到全量为准；同一输入 epoch 不因收到全量而将待确认输入视为已终结。 |

**P0 默认值**：单次重演最多 `32` 个模拟 Tick、每个控制者输入 epoch 最多保留 `64` 条待终结命令。两者分别约束工作量和内存，不是其他缓冲的容量或吞吐保证；生产没有接线。到达上限先保留证据、不淘汰未终结命令；若下一条无法进入有界历史，停止本地预测步进并清掉预测覆盖，不阻断原有权威输入路径。只记录未入历史输入的最大序号及最大计划 Tick，不伪装成空 Tick；同 epoch 下须有可信锚点和有效水位分别覆盖两个上界，并重新证明拟重演区间完整，才恢复预测。显式新 epoch 可废止旧缺口。首阶段不做自动输入重排、重发、全量请求或自动调参。

## P0 原型接线与验收

原型见 [`LocalMovementReconciler`](../Runtime/StateSync/Prediction/Reconciliation/LocalMovementReconciler.cs)。每个实例只服务一个作用域，在单一执行线上调用：

1. 用 `TryRecordInput` 按正序号递增记录命令，再用 `SealTick` 声明该 Tick 输入齐全，空 Tick 也须显式封存。重复的同序号、同计划 Tick 记录不覆盖已存值；迟到或不能安全收录的输入形成覆盖缺口。只把返回值用于本地预测，不用它拦截权威输入。
2. 用 `Reconcile` 交付已提交的投影和与修订、范围、Tick 精确匹配的终结证明；修订号须为正且递增，同 Tick 可有新的已提交修订。原型只验证证明绑定及水位单调，不能验证真实服务端是否终结输入；这是宿主的责任。
3. 用 `TryGetPrediction` 取成功的隔离候选，失败时可用 `TryGetAuthoritative` 取可信权威值。仅由宿主报告的 `InvalidateBaseline` 进入全量门禁；原型不发恢复请求，测试只验证门禁，不替代现有导入器或固定基线链的验收。

移动状态和命令为自包含值，不通过引用或句柄修改真实世界。P0 的 12 个本地用例通过，`.NET` 包回归 `68/68`；未运行 Unity。P1 仍须补真实移动状态账本、输入终结来源和适配方案，并另行确认。

## P1 前置验证：仅本地（2026-11-22）

两处提交都完成后的交付边界及本地夹具用例，见[离线权威提交结果契约](LocalCommittedStateResult.md)。夹具不代表生产已接线。

**验收约束**：只读本仓库源码，用测试进程内的自建类型化对象验证。不抓包、不查询线上输入终结水位、不读取或解析网络载荷，不启动联机会话或检查外部进程、内存及对象。本批不改运行时、协议、固定基线或帧同步链。

- **提交门禁**：[本地状态提交示例](../Samples~/LocalStateCommit/README.md) 和 P0 原型的联动测试只在隔离导入成功后交付新截面。失败候选不推进锚点、不重演，也不能凭其随附证明裁剪输入；提交成功但缺少匹配证明时仅接受权威锚点。夹具没有修改真实世界，不替代生产导入失败后的基线失效与恢复流程。
- **全量恢复门禁**：同一夹具显式报告基线失效。即使值提交示例接受了增量，P0 也不会将它采纳为权威锚点；旧全量和导入失败的全量同样不能解除等待。成功提交的新全量可以恢复权威读数，但仍需要同截面的输入终结证明才能裁剪输入，并在覆盖完整时重演。这验证的是本地门禁，不证明生产侧已完成全量导入或基线重建。
- **输入终结**：`LocalInputTerminalEvidenceTests` 用内存模型区分入队、改期、已应用和终局拒绝，只采纳截面完成时已确定的结果。若截面已包含前缀之外的高序号输入效果，即使能算出较低的连续前缀，也不提供证明；对账器保留待终结输入和权威投影、关闭预测。等低序号终局拒绝、剩余改期命令完成且截面包含其结果后，才裁剪连续前缀。该夹具不代表生产已有终结来源：`BattleLogicHostGrain.SubmitRuntimeInputs` 记录的是运行时接收提交后每玩家的最大序号，不能证明连续终结，也不能替代同截面提交。
- **普通移动**：`MobaLocalMovementEvidenceTests` 用真实 `MobaMotionLocomotionInputSystem`、`MobaMotionTickSystem` 完成权威锚点。隔离端复制姿态、运动状态和持续输入的值，用独立 `MotionPipeline` 和世界空间 `LocomotionMotionSource` 步进。试验提供固定步长和逐 Tick 移速、移动与转向许可；对照两个固定步长下的空输入 Tick、改向、移速变化、门禁变化及显式停止。逐 Tick 比较位置、旋转、缩放、前向、速度、时间和应用位移，并确认候选步进不修改权威姿态、运动状态或采样源输入。
- **接入缺口**：测试直接取得内存锚点和所需依赖，不能证明固定基线已提供这些值或未来 Tick 的依赖。碰撞环境、受管位移、技能后摇及其他玩法回调不在验证范围；未验证真实服务端终结、状态同步重建后的完整接线、远端表现或 Unity。生产接入前须另定同截面终结来源及最小移动投影，不混用帧同步确认；证明或依赖缺失时保持权威显示，不启用预测。
