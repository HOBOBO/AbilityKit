# 帧同步接入契约

## 从本地帧驱动开始

1. 宿主确定固定步长、业务命令键和同帧排序规则。键相同会替换；需要同帧执行多条命令时用不同键，比较器应提供稳定的完整排序。
2. `FrameCommandBuffer` 只存命令；由宿主额外记录帧是否已齐备。空桶、未到帧和已裁剪帧都可能返回零条命令，不能据此决定可以步进。
3. 宿主先执行该帧命令，再推进实际世界；完成后记录该世界已推进的帧。只有需要回滚时才额外接入检查点和输入历史；恢复及重演责任按业务状态归属声明。

## 默认值、所有权与扩展

| 关注点 | 合同 |
| --- | --- |
| 保留窗口 | 默认 `120`，最小 `1`。这是裁剪跨度而非硬容量；须在宿主确定安全边界后调用 `TrimBefore` 或 `TrimToWindow`。 |
| 迟到命令 | `SubmitCommand` 会把低于写入下界的帧归到下界。必须保留原帧号的权威结算记录应在适配层独立校验，不要依赖这个入口重排。 |
| 读取所有权 | 命中返回独立字典副本，未命中返回共享只读空集合。命令对象本身不深拷贝；优先传值或不可变命令。 |
| 并发 | 单次集合操作由锁保护；外部目标列表和比较器归调用方。组合读取、就绪检查和世界推进仍应由同一模拟执行线协调。 |
| 确认边界 | `LatestFrame` 是写入上界，不是已模拟帧、已结算帧或状态同步的输入终结证明。 |

实际装配可替换输入来源、命令执行策略和状态恢复 Provider；不要让这些适配改变世界规则或把状态同步投影当成可重演的整世界状态。旧资料见 [定点帧同步接入指南](../Document/定点帧同步接入指南.md)，本地验证见 [离线示例](../Samples~/LocalFrameCommands/README.md) 和 [包级验收](../Tests/README.md)。
