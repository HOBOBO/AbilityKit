# 观测关联原语契约与准入复核

`AbilityKit.Core.Observability` 当前包含三个值类型关联标识、同步尝试接收接口及正式空接收器。它们不表达战斗事件内容，不负责采集、对象分配、调度、队列、存储或可视化。源码位于 `Runtime/Observability/ObservationPrimitives.cs`，同文件内的类型共同构成这个窄范围契约。

本轮仅整理既有 API，未将这些类型标记为弃用，也未完成其正式发布准入。当前符号盘点发现的生产引用集中在 MOBA 诊断链；同项目的 runtime、trace adapter 和 editor 不构成三个相互独立的框架使用方。现有类型虽然具备领域中立的表面语义，仍缺少 [Core 纳入规则](./CoreBoundary.md) 所需的独立使用证据。它们已登记在 PublicAPI.Unshipped，本批保持该清单，不将“已存在、测试通过”作为正式准入证明。

## 值类型的有效性

三个构造方法都原样保存参数，不抛出参数范围异常、不修正无效值。需要有效值的调用方应自行检查 IsValid，但该检查只表示字段组合符合最低约定。

| 类型 | 有效条件 | 允许及不保证的行为 |
|---|---|---|
| `RuntimeObjectKey` | RuntimeId 非零且 Generation 非负 | 负 RuntimeId 可以有效，Generation 默认零；不分配标识、不递增代次，不验证目标是否仍存在。 |
| `ObservationDefinitionRef` | Kind 和 Id 均非零 | 两个字段都允许负值；不解析定义、不维护种类枚举，不保证配置存在或不可变。 |
| `ObservationTraceRef` | RootId 或 ContextId 至少一个非零 | 负值可以有效；ParentId 默认零且不参与有效性。只有 ParentId 的引用无效，不检查父子关系、循环或根与当前标识是否相同。 |

默认结构体的全部字段为零，三个类型均无效；这不妨碍其作为值保存、比较和查询。各标识的分配空间、跨世界/跨会话唯一性、回收复用、代次溢出、持久化及解析都由领域所有者负责。特别是相同 RuntimeId 与 Generation 在不同所有者空间中仍会比较相等，键中没有隐含世界或会话字段。

RuntimeObjectKey 不拥有对象生命周期，DefinitionRef 不拥有定义，TraceRef 不创建执行上下文。IsValid 为真不证明目标存在、可解析、仍存活或已通过领域校验。

## 身份、哈希与复制

相等比较包括所有字段：运行键的运行标识和代次、定义引用的种类和标识、关联引用的根/当前/父标识。即使值无效，比较仍逐字段执行；不能把全部无效值折叠成一个相同值。ParentId 不影响 TraceRef.IsValid，但影响相等及哈希。

同类型 Equals、装箱 Equals、== 和 != 采用相同身份规则；装箱的其他类型和空引用不相等。哈希与相等保持一致，但允许不同值碰撞，只用于集合查找；不要将当前哈希数字当作持久化身份、线上协议或跨运行时确定性约定。需要稳定外部标识时应使用领域明确的编码。

三个 readonly struct 只含整数值，没有共享可变实例状态；赋值和传参复制值，不保留对象引用。调用方仍需同步共享变量的发布和更新，不能把“值不可变”推导成多字段共享读写具有原子事务。

## 同步尝试接收

`IObservationSink<TEvent>` 仅约束事件为结构体，并提供 IsEnabled 与 TryWrite(in value)。结构体仍可包含可变引用，`in` 也不构成深度不可变、零复制或事件所有权转移保证。

IsEnabled 是当前接收意愿提示，接口没有自动检查，也不把读取与写入组成原子操作。读取为真后，TryWrite 仍可返回假；调用方不得把一次提示当作后续接受保证。

TryWrite 同步返回本次是否被接收，但“接收”不代表持久化、投递成功或下游处理完成。接口本身没有队列、线程切换、重试、顺序、容量、背压实现或异常隔离。具体实现须说明：是否复制/保留事件、如何管理引用成员、返回假或抛错前的副作用、线程安全和重入规则。调用方也不能假定同步方法返回后 sink 仍持有事件，或假定事件一定没有被复制。

这里没有通用调度实现，因此仅从接口本身无法测试所有实现的失败/启用行为。本批未通过编写一份测试 sink 并验证它自身，来宣称接口自动具备原子接收、异常隔离或所有权管理。

## 正式空接收器

`NullObservationSink<TEvent>` 是正式空对象，每个封闭事件类型有一个共享实例，构造方法私有。IsEnabled 恒为假，TryWrite 恒返回假；不检查事件有效性、不调用事件的相等/哈希/格式化方法，不保留事件或修改其引用成员，也不读取配置。

空接收器没有可变实例状态，可供并发调用复用。不同封闭事件类型不共用同一个实例；它也不释放事件或其引用成员。调用方若已创建事件并持有资源，接收失败后的资源责任仍由调用方的领域契约决定。恒返回假和空构造方法都不是未完成占位，不应在临时代码清理中删除。

## Core 定位与正式发布决策

本批保留现有路径、命名空间、签名、默认值和行为，不新增使用方来凑准入数量。真实使用证据尚不能支持将其宣布为 Core 正式基础面；公开 API、注释与测试完备和职责准入是不同检查项。

正式发布前需补充独立使用方对相同标识、有效性和同步接收契约的需求证据。若仍仅由 MOBA 诊断链需要，建议按实际所有权迁回该领域，或在 Diagnostics 存在独立共享需求时由其评审承接；迁移还需明确命名空间、依赖闭包、兼容窗口和升级影响。本批没有执行迁移、增加弃用标记、修改领域机制或将职责转交给尚未批准的新包。

领域采集策略、事件内容、标识分配和持久化继续由所有者承担，不能因这些原语已在 Core 中存在，就继续添加统一事件严重级别、观测调度器或通用对象目录。

## 验证范围

本批新增 26 项直接契约测试，覆盖边界取值、无校验构造、有效性、默认参数、父字段身份、无效值集合键、装箱和运算符一致性，以及空接收器的实例边界、事件方法不执行与并发拒绝。原有六项 ObservationPrimitivesTests 保留。

证据来自 .NET 10，源码去注释后与批次备份一致，未更新 API 基线或 Unity 元数据。本批没有运行 MOBA 业务回归，没有把 Core 单元测试作为真实消费方验收；Unity/Mono/IL2CPP、独立干净消费、准入复核和正式发布评审仍待完成。
