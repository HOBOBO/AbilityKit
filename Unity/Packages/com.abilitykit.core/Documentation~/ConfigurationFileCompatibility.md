# 配置文件、缓存与模块描述兼容契约

`Runtime/Config` 的应用配置 API 已弃用，保留至下一主版本移除窗口。文件路径、序列化器、缓存更新和模块安装属于应用或引导包的策略，不再作为 Core 新能力扩展。本页详细说明 JsonSettingsFiles、PersistentJsonConfigLoader、ModuleInstallerConfig 与 ModuleInstallerConfigSet。

扁平读取和分层合并继续使用既有 [FlatJsonSettings](../Runtime/Config/FlatJsonSettings.cs) 与 [LayeredJsonSettingsStore](../Runtime/Config/LayeredJsonSettingsStore.cs) 契约；本批未重写它们。包内的旧 UnityJsonSettingsBootstrap 仍调用 Core 文件工具；同名 MOBA 类型则属于独立的应用命名空间，不能根据短类型名判断依赖或行为等价。

## 设置文件读写

LoadFlatOrEmpty 将路径交给 Path.GetFullPath，同步读取文件，再调用 FlatJsonSettings.FromJson。它不缓存文件或设置，也不额外验证 JSON 语法、规范化文本或选择序列化器。

| 读取情况 | 结果 |
|---|---|
| 空路径、文件不存在、目录路径、读取或路径解析异常 | 返回新的空设置，不提供具体失败原因。 |
| 空文件文本或空反序列化委托 | 返回空设置，不调用反序列化器。 |
| 非空文本，包括空白或非 JSON 文本 | 原样交给调用方回调，由回调解释内容。 |
| 回调返回空字典引用或抛出异常 | 返回空设置。 |
| 回调返回字典 | 复制字典结构，键按序号比较，值对象保留原引用。 |

TrySaveOverrides 在空序列化器或空路径时直接返回假。其余步骤依次为解析完整路径、创建父目录、调用序列化器、File.WriteAllText 直接覆盖目标文件。非空设置字典原样交给回调，不生成快照；空设置引用按新的空字典处理。序列化器返回空引用会转成空字符串写入，返回文本不验证是否为 JSON。

捕获异常时返回假，但不会回滚已经创建的父目录、执行过的回调副作用或可能发生的文件变更。序列化器抛出时尚未执行本工具的写入，因此既有文件内容不会因该次工具写入被覆盖；回调自身的外部操作另由调用方负责。写入没有临时文件、原子替换、备份或跨调用同步，不能把失败理解成“目标保持原样”，也不能把成功理解成额外的断电持久化保证。

## 持久化对象缓存

TryLoad 首先拒绝空反序列化委托与空路径，随后解析完整路径、检查文件存在并读取 LastWriteTimeUtc，再检查静态缓存。缓存键由完整路径字符串和请求泛型类型组成，路径采用序号相等比较。它不按文件系统大小写、符号链接或文件身份合并别名，也不将回调委托纳入键。

| 缓存条件 | 实际行为 |
|---|---|
| 同路径、同请求类型、相同写入时间 | 返回缓存原对象，不读取文本或调用新回调；对象的外部修改后续仍可见。 |
| 同一文件，以不同泛型类型请求 | 分别缓存，即使反序列化对象运行时类型相同。 |
| 写入时间改变 | 重新读取和解析，即使文件内容没有变化。 |
| 文件内容或长度改变，但时间保持相同 | 仍可命中旧对象；不检查长度、哈希或内容版本。 |
| 回调正常返回空值 | 缓存空值，相同时间后续不重试回调。 |
| 空文件文本 | 返回空值，不调用回调，也不写入新的缓存项；空白文本则仍交给回调。 |
| 文件不存在、读取或回调异常 | 返回空值，不返回旧缓存，也不删除旧缓存项；文件重建或时间恢复后旧项仍可能再次命中。 |
| 回调为空，即使已有缓存 | 先返回空值，不查询缓存。 |

字典只在查询、提交和清空时加锁。文件读取与反序列化均在锁外，没有单次加载合并或文件快照。并发未命中可以多次调用不同回调，调用者各自拿到自己的结果，后提交者覆盖缓存；这并不保证后提交者读取的是较新的内容。写入时间在读取文本之前取得，文件在加载期间改变时，本次结果和记录时间也不构成原子快照。

ClearCache 仅在锁内清空当前字典，不 Dispose 返回对象，不清空使用方持有的引用，也不取消在途加载。在途回调甚至可以自己 ClearCache，外层加载返回后仍会重新提交。缓存没有容量上限、过期淘汰、弱引用或所有者作用域；需要更强一致性和生命周期的应用应迁移到自己的加载契约。

LoadOrDefault 先调用 TryLoad，返回空值时每次执行 new T()；默认实例不写入缓存。默认构造在 TryLoad 的 catch 之外，构造失败会传播。回调返回空值被缓存时，也仍可能每次创建新的默认实例；不能用默认实例的存在证明文件读取或反序列化成功。

## 模块配置与查找

ModuleInstallerConfig 是三个公开可变字符串字段：ModuleKey、InstallerType、InstallerMethod，默认均为空字符串。IsValid 只检查模块键和类型字符串是否非空，空白字符串仍有效；它不解析类型、不检查方法、签名、安装资格或依赖。GetEffectiveMethod 仅在方法名为空引用或空字符串时返回历史默认值 InstallAsCurrent，其他名称原样返回。

ModuleInstallerConfigSet 默认持有空数组，允许调用方替换数组和修改元素。FindModule 保存当前数组引用后按数组顺序遍历，忽略空元素及无效配置，以 StringComparison.Ordinal 比较键，返回首个匹配的配置原引用。重复键不合并、不报错、不选择最后一项；大小写及前后空白不自动归一化。空查询键不可能匹配有效配置，空数组引用也返回空值。

查找不会深复制、排序、安装模块或保证并发安全。配置字段、数组内容或数组引用的变更会影响后续查找。有效配置和有效方法名都不是安装成功的证明。

## 实现审查与迁移边界

读取返回空设置、保存返回假、持久化加载返回空值的 catch 均是既有兼容失败策略；默认对象和历史安装方法名也承担现有契约，不能按占位代码删除。本批保持实现、默认值、公开签名、源码路径与 Unity GUID。

应用设置的目标所有者为应用自己的设置模块；当前 MOBA 对应 AbilityKit.Demo.Moba.View.Settings，引导配置对应 AbilityKit.Demo.Moba.Bootstrap。迁移时需要同时核对空文件、失败诊断、覆盖写入、缓存键及失效、对象共享、默认值、重复模块键和线程所有权，不能仅替换 using 或复制静态工具便认定等价。Unity 的路径和持久化适配仍应由视图或宿主所有者承担。

若应用需要原子保存、内容版本、并发失效屏障或安装流程，应先明确失败后责任和迁移影响，再在所属包设计。本批不扩展 Core 应用配置职责。

本批直接测试在独立临时目录中显式设置并验证时间戳，使用信号控制并发顺序，没有依赖自然时间等待。证据覆盖 .NET 10 文件与缓存契约；未穷举磁盘满、断电和平台权限差异，也未完成旧 Unity 适配器的真实 Unity/Mono/IL2CPP 编译或干净消费验收。
