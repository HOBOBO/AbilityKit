# Marker 注册与扫描兼容契约

`AbilityKit.Core.Markers` 保留既有特性、注册表和反射扫描构件，供现有使用方迁移。它不提供代码生成、编辑器发现、宿主启动或实例生命周期管理。新增发现策略由所属领域或应用所有者控制，不继续扩展 Core 的程序集发现职责。

`MarkerSystem` 和三个 Bootstrapper 基类已标记 Obsolete，并冻结到下一主版本移除窗口；特性、注册表和基础扫描器目前没有该 API 弃用标记。兼容构件的保留不代表新项目应接入全局启动入口。准入规则以 [Core 边界](./CoreBoundary.md) 为准。

## 登记与实时视图

`MarkerAttribute.OnScanned` 默认不执行操作。派生特性决定是否调用注册表、如何提取键以及领域约束；基础扫描器不替它自动登记。

| 入口 | 既有行为 |
|---|---|
| `MarkerRegistry<TAttr>.Register(type)` | 忽略空类型、抽象类型和接口；按 Type 默认相等比较去重，保持首次登记顺序。 |
| `KeyedMarkerRegistry<TKey,TAttr>.Register(type)` | 只向历史类型目录去重追加，不增加键或 Count。 |
| 键控 `Register(key,type)` | 先执行相同类型过滤，再按默认键比较器覆盖映射，并向历史类型目录去重追加；被替换的旧类型仍在目录中。 |
| 普通 Count / 键控 Count | 分别统计类型数和键数；键控 Count 不一定等于 Types.Count。 |
| `Types` | 返回底层 List 的实时 IReadOnlyList 接口，没有复制或只读包装；应只读使用，接口类型不保证对象不可变。 |
| `Keys` | 当前字典键的实时视图，不保证跨运行时的枚举顺序。 |

两个实现均不读取 TAttr、不检查类型有无标记，也不验证开放泛型或构造条件。手动登记值类型、无标记类型、开放泛型都可能成功。键控无效类型会在访问键前被忽略；有效类型配空键则沿用字典的参数异常。TryGet 缺失输出空类型，Get 缺失抛 KeyNotFoundException。

普通 ForEach、Find 和延迟 Where 均按实时列表和实时长度遍历，回调追加项可能进入同轮。Where 到枚举时才执行谓词和传播异常，Find 返回首个匹配或空值。它们不前置验证委托：空列表传空委托可无动作，有元素时才失败。键控 ForEach 直接枚举字典，修改期间的有效性沿用目标运行时字典规则，不应依赖某个 .NET 版本允许覆盖值的特性。回调异常直接传播，已有登记不回滚。注册表没有并发保护或重入事务屏障。

## 实例创建

两个 `GetOrCreateInstance` 重载都不缓存，每次命中通过 Activator.CreateInstance 新建对象。键缺失返回空值；泛型重载先检查可赋值关系，不匹配时返回空值且不执行构造。无参构造缺失、开放泛型、访问限制和构造器异常由反射传播，构造器抛错可带 TargetInvocationException 包装。登记成功不表示之后能实例化；对象的释放和复用由调用方负责。

## 基础扫描

`MarkerScanner<TAttr>.Scan(Assembly[], IMarkerRegistry)` 是同步调用：

1. 注册表为空或数组为空时无动作，数组中的空程序集跳过。
2. 按输入程序集顺序及 GetTypes 返回顺序处理类型；重复程序集会重复触发回调，不跨轮记忆扫描结果。
3. 遇到 ReflectionTypeLoadException 时继续处理其 Types 中可用的非空项，忽略加载失败项；不把加载异常列表返回给调用方。
4. 跳过空类型、抽象类型和接口，只读取类型直接声明的匹配特性，不沿继承链读取。
5. 每个直接匹配特性都调用 OnScanned，顺序沿用反射结果，不额外排序。不自动调用 registry.Register，也不创建实现实例。

其他 GetTypes 错误、特性构造错误和回调异常立即传播并中止剩余扫描；之前的副作用保留。程序集、类型和特性顺序不应当作跨运行时确定性协议。调用方也须控制共享输入数组和回调副作用。

ScanAll 只取得当前应用域已加载程序集，不保证发现全部项目程序集。反射具有枚举、特性创建及分配成本，不能称为“零运行时开销”。裁剪保留、代码生成和 AOT 注册需要由所有者单独设计和验证。

## 扩展入口的差异

| 入口 | 范围及限制 |
|---|---|
| `ScanAllExcludingSystem<TAttr>(excludeSystemAssemblies = true)` | 对已加载程序集应用固定、区分大小写的名称规则；这是部分名称过滤，不是完整系统分类。关闭过滤也仅扫描已加载项。 |
| `ScanExcluding<TAttr>(params string[])` | 按简单名称、不区分大小写精确排除，不含 .dll；空排除数组扫描全部已加载项。 |
| `ScanWithReferences<TAttr>(startAssembly,maxDepth = 2)` | 深度优先收集，按简单名称去重，可能主动 Assembly.Load。零深度只扫描起始项，负深度不扫描，空起始项无动作。到达深度边界仍会枚举并尝试加载引用，子项才因负深度停止收集。引用枚举/加载失败被隔离，实际扫描异常仍传播。空注册表不保证阻止先前的引用加载。 |
| `ScanByNamespace<TAttr>(string)` / `(string[])` | 忽略大小写，按文本前缀匹配而非命名空间段边界；跳过无命名空间类型。每个类型只调用首个直接匹配特性，与基础 Scan 的“全部特性”不同。 |
| `GetAssembliesByName(string)` | 从已加载程序集按简单名称子串、忽略大小写匹配，返回新数组；空字符串匹配全部，空引用由字符串 API 抛错。 |

命名空间数组为空、无元素或首项为空字符串/空引用时，整次操作无动作，即使后续项有效也不扫描；后续项不前置验证，空字符串可匹配任意命名空间，空引用可能在匹配时抛错。此入口没有注册表空值检查，回调可以收到空注册表。它同样保留部分类型加载恢复，其他错误直接传播且不回滚。

名称过滤规则、引用加载隔离与命名空间扫描并非等价实现，不能仅因循环相似就合并。后者“仅首个特性”等差异作为兼容限制保留，修改需单独评审升级影响。

## 已冻结的全局状态

MarkerSystem.Register 按特性类型、注册表引用和委托相等比较去重；完全相同的登记无动作，新增登记会清除 IsInitialized 并改变版本。运行时类型入口只验证非空和可赋给 MarkerAttribute，闭合泛型等反射条件仍可能失败。Register 只登记，不扫描。

GetRegistry 返回登记顺序中的首个兼容实例。GetRegistrations 返回新数组浅快照，登记项和注册表引用仍共享，既有快照不随 Reset 清除。TotalScannedTypes 实际是登记快照中各 Registry.Count 的当前求和：同一注册表用于多个登记项会重复计数，键控表统计键，它不是扫描总数或唯一类型数。

ScanAll 对非空输入每次重新扫描，不因已初始化而跳过。每轮先取得登记快照、清除标记并推进版本，全部成功且版本仍匹配时设为已初始化；即使无登记项，非空输入也可设为已初始化。空输入不改变标记。

过滤器先处理整个输入数组，再执行该登记项的扫描；过滤器能收到原数组中的空项。过滤异常直接传播，反射扫描异常保留 TargetInvocationException 包装；后续登记项停止，已完成的副作用保留。独立构造 MarkerRegistration 不加入全局系统，它也可直接扫描，不自行管理全局标记。

登记锁只保护结构和状态，扫描锁在过滤/扫描期间持有，并允许同线程重入。回调可新增登记或 Reset，新登记不进入外层快照，版本变化阻止外层正常完成时重新设标记。Reset 不等待在途扫描，不清空或释放外部注册表，也不阻止旧快照继续产生副作用。

IsInitialized 不是完整启动成功证明。内层扫描成功后，外层再抛错仍可能留下真值；它不能充当重入屏障或宿主事务状态。外部注册表、回调及多步工作流仍由所有者同步，不因局部锁而变为线程安全。

## 引导兼容与迁移

两个实例 Bootstrapper 在**基类实例构造**期间读取 AutoRegister（默认真）及 AssemblyFilter 并登记，不是静态构造，也不执行扫描。这些是构造期间的虚调用，派生实例尚未完成初始化。空注册表被拒绝；禁用 AutoRegister 时不读取过滤器；属性或登记失败不回滚外部副作用。

StaticMarkerBootstrapper 按每个封闭泛型的运行时静态初始化规则，创建 TSelf 并调用 Register 一次。默认 Register 调用 CreateRegistry 与 AssemblyFilter 登记全局项；重写可不登记。EnsureInitialized 的静态方法调用会先完成声明类型的静态构造，方法内的 typeof 本身不是实例创建机制。Reset 后再次调用不会重新登记；静态构造失败沿用运行时失败缓存和包装语义，部分登记不回滚。仅加载模块文件或取得类型信息不保证触发启动。

迁移时先由所有者明确类型范围、登记顺序、冲突策略、实例所有权和失败责任，再改为显式或生成式注册。不要通过新增全局扫描器、宿主默认自动启动或 Core 内领域特例替换旧入口；也不能假定生成式路径已验证裁剪或 IL2CPP。

## 验证与边界

`MarkerCompatibilityContractTests` 直接覆盖登记、实时/延迟查询、创建实例、可控程序集部分加载、扫描回调、名称/命名空间/引用辅助入口、全局状态重入及引导副作用。操作 MarkerSystem 的新旧测试共用一个 xUnit 集合进行状态隔离，不禁用整个测试程序集的并发。

本批证据来自 .NET 10。没有完成 Unity/Mono/IL2CPP、所有反射失败分支、跨运行时字典变更行为或独立干净消费验证。兼容契约整理不代表全局发现重新满足 Core 定位，也不代表正式发布完成。
