# Core Continuous 兼容与迁移契约

`Runtime/Continuous` 是已弃用的旧生命周期 API，命名空间为 `AbilityKit.Core.Continuous`，仅保留至下一主版本移除窗口。持续行为的正式所有权属于 `com.abilitykit.continuous`，新代码采用 `AbilityKit.Continuous`。本页描述旧 Core 的实际行为，不授予新增 Core 使用方或扩展领域机制的资格。

## 职责与配置

`IContinuous` 实现负责状态转换、经过时间和结束事件。接口没有 Tick 或 Update，默认管理器不推进时间，也不自动执行时长、互斥、优先级、层级、级联或叠加策略。可选配置接口仅提供数据；实现 `IDurationConfig` 并不会得到自动到期能力。

默认管理器负责登记、所属实体索引、准入和生命周期通知。它非线程安全，调用与回调同步发生，不切换线程。登记期间必须保持配置、OwnerId、哈希及相等性稳定；生命周期操作应使用原登记实例。集合采用默认相等比较，而非引用身份；不同实例的配置 Id 相同不会自动合并。

## 登记、准入与注销

Register 在入口清空 LastRejectReason，拒绝空对象或空配置；重复登记直接成功，不重复准入和通知。策略按列表顺序执行，在首个拒绝处停止，异常直接传播。构造器复制输入序列，不去重、不筛除空元素；调用方应提供有效元素。Add 方法忽略空值及已有项，Remove 方法按默认相等比较移除首项。

登记顺序为：写入登记及所属实体索引、订阅结束事件、调用注册绑定器快照、触发公共 OnRegistered 事件。绑定器失败时先撤销登记，再对已尝试绑定器倒序调用 OnUnregistered(CleanedUp)，包括抛异常者；补偿异常隔离，以保留原始注册异常。尚未尝试的绑定器不补偿。公共注册事件位于回滚边界之外，其异常传播且保留登记。

Unregister 先移除索引及订阅，再调用当前绑定器和公共注销事件。它不调用 End 或 Abort，不保证对象终止。绑定器异常会阻止后续通知，已经完成的移除不回滚。Clear 按注册顺序复制列表再逐项注销，同样不结束对象。

## 生命周期及失败结果

| 操作 | 旧 Core 实际行为 |
|---|---|
| TryActivate | 先自动登记，再检查激活准入；终止对象也可能先完成登记再被拒绝。调用 Activate 后按 IsActive 更新活动索引，仅在此前非激活而当前激活时通知绑定器及公共事件。重复激活仍再次调用对象方法。 |
| TryPause | 不要求已登记；对激活且未暂停、未终止对象调用 Pause，只有调用后已暂停才移除活动索引并通知。 |
| TryResume | 不自动登记；暂停对象通过激活准入后调用 Resume，只有调用后激活才加入活动索引并通知。成功不清空旧 LastRejectReason，准入拒绝才写入新原因。 |
| TryEnd | 不要求已登记；对非空、未终止对象调用 End，返回其终止标记。已登记对象依赖实现发出 OnEnded 完成清理，管理器不补发事件。 |
| TryInterrupt | 不要求已登记；另检查 CanBeInterrupted，然后调用 Abort，文本原因交给实现。结束事件的枚举原因由实现提供。 |

TryActivate 在入口清空 LastRejectReason，Register 也会清空；不能将该属性理解成每个方法都刷新的一致错误状态。其余生命周期回调异常直接传播，不回滚已经提交的状态或索引。尤其激活绑定器失败后，旧 Core 保留已激活对象及登记，不自动终止。

收到 OnEnded 时，管理器先移除活动索引，再通知结束绑定器，最后在 finally 中尝试 Unregister。结束绑定器运行时对象仍处于登记中；若注销也失败，finally 的异常会覆盖此前的结束异常。事件原因原样透传。protected ResolveEndReason 是保留的兼容扩展点，默认结束链并不调用它。

## 查询、批处理与重入

| 查询 | 顺序与视图 |
|---|---|
| GetOwnerContinuous | 注册顺序，当前所属实体列表的只读实时包装。最后一项移除后列表从字典删除，已有包装不会跟随之后新建的列表；未找到时为空数组。 |
| GetOwnerActiveContinuous | 所属实体注册顺序，按实时 IsActive 且未终止筛选，返回副本。 |
| GetAllContinuous | 全部登记顺序的副本。 |
| GetAllActiveContinuous | 按全部登记顺序筛选活动索引成员，返回副本，不重新判断实时状态。 |
| TotalCount / ActiveCount | 分别为登记集合与活动索引大小，不是实时状态扫描。 |

直接调用对象的 Activate/Pause/Resume 不会自动同步活动索引。对未登记的暂停对象 TryResume 可能令 ActiveCount 大于 TotalCount；该对象不会出现在按登记顺序生成的全部活动快照中，未登记的 Unregister 也不会清除此活动项。这是旧版限制，调用方应经管理器登记并统一协调生命周期。

PauseAll、ResumeAll、InterruptAll 先复制所属实体列表。回调新增对象不进入本轮，快照内被注销的对象仍可能被后续单项操作。Clear 的回调新增登记也可能保留。任意异常都会中断本轮，保留此前进度。

只有注册绑定器采用快照；其他绑定器通知及准入使用实时列表。回调中增删会影响本轮后续调用，不应依赖跳项或新增项的遍历副作用。管理器没有事务、代次或通用重入屏障：注册绑定器可重入注销，外层 Register 仍可能返回成功并触发注册事件，而对象已不在登记集合中。此类限制通过兼容测试记录，新增重入机制需单独设计。

## 内置策略与保留实现

`BlockByOwnerActiveTagsPolicy` 只检查同一 Owner 的其他实时活跃对象，按引用跳过目标自身。若其标签与构造时传入的容器匹配，则拒绝激活或恢复；不限制注册。它保存容器引用，因此容器后续变更会影响判断。空目标、空管理器、空标签容器或零标签数量时直接放行。它不读取目标的 PauseByTags/BlockByTags，也不会自动暂停、恢复、互斥或替换对象。

`AllowAllContinuousAdmissionPolicy` 仍检查登记对象及配置非空、激活对象非空且未终止；它即使拒绝也返回空原因。`NullContinuousLifecycleBinder` 是可选装配所需的正式空对象。注册补偿中的异常隔离用于保留原始失败。这些实现并非待删占位。

## 迁往独立包

1. 将依赖与命名空间迁到 `com.abilitykit.continuous` / `AbilityKit.Continuous`，逐项迁移持续体、配置、策略及绑定器实现；两个命名空间的类型不能互相替代。
2. 核对目标包当前源码及其测试，重点覆盖失败后所有权、异常身份和回调顺序。当前独立包在激活绑定器失败时会尝试结束并注销持续体，旧 Core 则保留激活与登记；迁移不能只替换 using 并假定行为等价。
3. 用实际项目场景验证暂停/恢复、结束事件、批处理、配置策略及宿主计时；保留回退和兼容移除计划。Core 本批未新增转发适配或改变独立包实现。

本批的 .NET 契约测试及注释检查仅证明记录的范围。Unity、Mono、IL2CPP、独立干净消费及正式发布评审仍需单独完成。
