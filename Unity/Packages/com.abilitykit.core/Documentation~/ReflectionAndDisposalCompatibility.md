# 反射与释放工具兼容契约

`AbilityKit.Core.Reflection.ReflectionInvokeUtils` 与 `AbilityKit.Core.Utilities.DisposeUtils` 已弃用，仅保留至下一主版本移除窗口。新代码应将发现、装配与释放策略放在资源或领域所有者内部，不新增这两个 Core 入口的生产使用方。本页记录旧实现的实际行为，供兼容维护和迁移核对。

## 类型查找

FindType 对空引用或空字符串返回空值。其他输入先交给 Type.GetType；成功便直接返回，否则枚举 AppDomain 当前已加载的程序集，按枚举顺序调用 Assembly.GetType 并返回首个结果。名称区分大小写，本工具不额外裁剪或规范化；具体名称语法遵循运行时规则。结果没有缓存。

Type.GetType 不等同于只扫描已加载程序集，程序集限定名可能触发加载或解析回调。首次解析位于 try/catch 之外，即使 throwOnError 为假，其他解析或回调异常仍可能传播。后续程序集枚举则整体位于异常隔离中：一旦枚举或某个程序集查找抛出异常，就结束本次遍历并返回空值，不会保证继续检查剩余程序集。

程序集枚举不额外排序。同名类型的胜出不具备跨运行时的稳定顺序，也没有“优先项目程序集”或“仅公开类型”的策略。查找成功不证明该类型满足业务约束。

## 静态调用

两个 TryInvokeStaticMethod 重载都在异常隔离范围内执行类型查找，随后使用 BindingFlags.Public | BindingFlags.Static 按名称查找方法，再以空参数调用。它们没有根据零参数签名选择重载，也没有参数填充、泛型闭合、返回值检查或异步等待。

| 情况 | 带异常输出重载的结果 |
|---|---|
| 类型或方法未找到 | 返回假，exception 为空。类型未找到时不会继续检查方法名。 |
| 方法名为空引用且类型存在 | 返回假，exception 为实际捕获的参数异常。 |
| 同名方法构成重载歧义 | 返回假，输出 AmbiguousMatchException；即使其中有零参数重载也不自动选择。 |
| 只有带参数的方法 | 返回假，输出参数数量异常；可选参数和 params 数组也不会自动填充。 |
| 开放泛型方法 | 返回假，输出运行时拒绝直接调用的异常。 |
| 目标方法同步抛出 | 返回假，保留反射返回的 TargetInvocationException 及其 InnerException，不自动解包。 |
| 方法正常返回 false、空值或其他值 | 返回真，exception 为空，目标返回值被丢弃。 |
| 方法正常返回一个失败的 Task | 返回真，exception 为空，不等待或解释该任务的完成结果。 |

不带异常输出的重载对相同查找及调用失败返回假，丢弃异常信息。exception 为空不能单独证明成功，应同时检查布尔结果。方法名区分大小写；私有静态方法或实例方法不在指定标记的查找范围内。其他继承、绑定及名称行为以这些反射标记和目标运行时为准。

所有反射调用同步发生，不切换线程，也不捕获异步任务后续执行阶段的失败。这里没有程序集发现服务、统一启动流程、线程安全装配、裁剪保留、泛型代码生成或 AOT 注册保证；.NET 测试不能代替 Unity/IL2CPP 验证。

## 释放与引用清空

DisposeUtils 提供接口引用和受 IDisposable 约束的类引用两组重载。四个入口都对空引用直接返回；非空时同步调用 Dispose，最后在 finally 中将传入的 ref 位置设为空。泛型重载只接受引用类型，接口重载仍可以持有装箱的值类型。

| 重载 | Dispose 抛出后的行为 |
|---|---|
| 不带异常回调 | 原释放异常直接传播，最终清空 ref 位置；TryDispose 名称不表示异常被吞掉。 |
| 带回调且回调正常返回 | 同步将原异常交给回调，随后正常返回并清空引用。 |
| 带回调且回调为空 | 兼容实现隔离释放异常，随后清空引用；公开参数的现有可空标注不在本批变更。 |
| 异常回调自身抛出 | 回调异常传播并替代原释放异常，仍最终清空引用；不自动聚合或设置 InnerException。 |

空引用和成功释放均不触发异常回调。释放失败后的空引用只表示该存储位置被清空，不能证明资源已成功释放或完成外部清理。工具不会重试、记录日志或接管失败资源的恢复责任。

## 重入、别名与替换

清空发生在 Dispose 以及异常回调之后。因此回调执行期间原引用仍然可见，重入同一工具可以再次调用相同对象的 Dispose。没有互斥锁、原子交换或“一次释放”屏障；不能将它等同于具备幂等保证的所有权句柄。

在一次正常调用返回并清空引用后，再次对相同空位置调用会无动作，但其他别名仍然可以访问或再次释放原对象。接口中装箱的值也不会因清空这个接口引用而改变其他副本。

若 Dispose 或异常回调期间把 ref 指向的位置替换成新对象，外层 finally 仍会把新值清空，也不会释放该新对象。调用方必须避免依赖这种替换进行资源转移，并负责仍存活的外部别名及新对象。并发修改同一引用位置同样不受支持。

## 保留实现与迁移

反射遍历的空 catch、调用失败返回假、异常输出重载及释放回调隔离均是既有兼容失败策略，不是待补占位。两个释放重载族保留其公开形态；本批没有将其合并成新通用工具，也没有扩大异常隔离范围或将引用提前清空。

迁移时，领域所有者应明确要发现哪些类型、采用何种注册顺序，以及启动方法的参数、返回值和异步完成规则；优先使用窄接口、委托或显式注册。需要裁剪或 AOT 的路径还应由目标包提供注册与平台验证。

资源所有者应明确释放顺序、异常传播或记录方式、重试责任、别名有效期及重入策略。如果目标设计要求回调前撤销引用，应单独评审这种行为变化，不能假定它与旧 DisposeUtils 等价。不要只把这两个入口搬到另一个通用静态类便视作迁移完成。

本批直接测试覆盖当前 .NET 10 的上述可复现分支；未通过故障注入穷举 AppDomain 程序集遍历失败，也未完成干净消费、Unity、Mono、IL2CPP 或正式发布验收。
